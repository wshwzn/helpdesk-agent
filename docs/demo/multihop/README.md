# 多跳开发资料与单轮基线

这是本项目原创的虚构资料，不对应真实企业制度。C1 固定样本并测量单轮 KNOWLEDGE 链路；C2 已实现受控补查，继续使用相同题集对照。

## 资料结构

```text
星桥计划 ──保障编码──> R7 ──住宿等级──> L2 ──上海──> 680 元
                                           └──北京──> 520 元
海岚计划 ──住宿等级──> L3 ──上海──> 760 元

所有计划 ──通用报销流程──> 结束后十五个自然日内提交
```

正文分布在 18 份文件中。14–16 是已失效、未生效、未审核干扰资料；17–18 是其他住宿等级的有效额度。除受地区限制的额度外，计划和映射均为 ALL。文件 01–18 参与导入，本说明不导入。

文件名和清单路径只供维护者使用，回答模型只收到按正常检索实际召回的片段。资料正文不包含标准答案列表、应有状态、步骤提示或题号。计划文件里的转引是模拟业务文件本身的依赖关系。

## 冻结题集

完整身份、有效期、发布状态、题目与金标准在 `docs/evaluation/multihop-cases.json`，版本 `enterprise-multihop-v1`。在第一次真实问答前冻结；如果后续改题或改资料，应升级题集标识并重新建立基线，不能直接比较旧成绩。

| 类型 | 题目 | 目的 |
| --- | --- | --- |
| 直接查询 | D01–D03 | 上海额度、报销期限、北京额度，作为简单问题控制 |
| 两跳 | H01 | 海岚 → L3 → 上海金额 |
| 三跳 | H02–H03 | 星桥 → R7 → L2 → 指定地区金额 |

“几跳”表示资料依赖链，不等于必须产生相同次数的搜索调用。单次 Top 5 恰好召回完整链时仍应正确回答，也不算多跳执行能力。N03 当前只检查未臆造金额及证据覆盖，C2 才能验证真正的重复查询/无新增证据停止条件。

## 执行

需要正在运行的后端、真实 MySQL/OSS/ES、默认 CHAT/EMBEDDING 模型，以及管理员、客户登录凭据。凭据从 `HELPDESK_ADMIN_USERNAME`、`HELPDESK_ADMIN_PASSWORD`、`HELPDESK_CUSTOMER_USERNAME`、`HELPDESK_CUSTOMER_PASSWORD` 环境变量或忽略的 `.env` 获取，不写入题集或报告。

```powershell
python -m unittest discover -s scripts -p 'test_evaluate_knowledge_multihop.py' -v
python scripts/evaluate_knowledge_multihop.py --output target/multihop-baseline-c1 --runtime-label a7299d0-single-pass --runtime-jar target/stage35-backend.jar
```

运行标签应与实际进程一致，`--runtime-jar` 记录指定制品摘要，不能单靠当前 Git HEAD 证明服务正在运行该版本。输出目录必须不存在，每题独立会话，失败不重试。真实失败会返回非零退出码，同时报告保留所有已执行结果。

脚本创建独立知识库，固定 candidateLimit=50、vectorMinSimilarity=0.65、resultLimit=5；不启用主题澄清配置，问题通过请求字段明确范围。导入完成后临时切换默认知识库，每题检查库、资料和模型配置是否变化，最后恢复原默认库。硬杀进程可能来不及执行恢复，可从 `results.json` 的 original.knowledgeBase.id 查看原库并用原 default 接口恢复。

## 结果口径

- **检索覆盖**：诊断中实际召回的来源是否包含题目所需全部来源；截断或缺失诊断记未知。
- **证据覆盖**：实际交给回答流程的证据是否完整，与检索覆盖分开保留。
- **自动检查**：状态、金标准来源引用、逐字引文、范围、发布/有效期和关键点。自动通过仍需语义阅读；不能只出现正确数字就算回答正确。
- **技术失败**：HTTP / 协议 / 复核拒绝等单列，失败也留在题数分母中，不能计为正确拒答。
- **金标准检索探针**：问答全部结束后，通过管理员 search 接口执行预先写好的查询；相同范围与查询只调用一次，复用结果。探针不喂给回答模型，不计入自动问答成绩，其额外 Embedding 调用与延迟单列。
- 已知回答 Token 不含 Embedding 或未知厂商用量；缺失用量不按零成本解释。单次开发集表现不是生产准确率。

基线必须保留模型名称/配置更新时间、检索参数、题集/资料/源码/JAR 摘要、原始诊断、结果和默认库恢复状态。后续多跳版本使用相同题集与配置比较，额外记录查询、轮次、去重、停止原因和模型成本。

## C2 运行

已有冻结资料库时可传 `--knowledge-base-id <库ID> --skip-probes`，省去重复导入和人工探针。运行前确认后端已启用多跳并填真实制品标签；题集与 18 份原文保持冻结。诊断 retrieval 是首轮，retrievalRun.searches 是全部实际搜索，evidence 是累计去重证据，规划模型生成的缺口不能当作事实依据。
