# 公开制度问答质量对照

本轮评测检索后的生成核验环节：真实检索快照固定后，比较同一初稿直接交付与增加语义复核、一次修订的结果。不是完整在线端到端测试，也不是人工评审的准确率。

## 数据与对照设计

- 沿用 23 份公开制度、91 个 chunk 的语料快照；70 条测试题加此前预留的 10 条资料不足问题，不根据生成结果删题。
- 有答案题使用上一轮保存的真实 RRF 前 10 个 chunk；无答案题使用相同知识库和检索参数重新获取前 10 个 chunk。全文及摘要留在本地。
- 两组共用一次草案生成，也都保留现有引用目录解析和结构校验。基线不做语义复核；完整组复用 `TrustedKnowledgeAnswerService` 的复核及最多一次修订。
- 检索器与资料资格检查在测试 CLI 中替换为冻结快照，其他生成、引用解析、语义复核、修订均调用生产代码和真实默认模型。未覆盖多跳规划、实时资料准入、历史上下文、HTTP、SSE及前端展示。
- 不切换用户默认知识库，不改生产业务逻辑，不写业务会话。三个线程仅用于运行离线实验。
- 参考原文只提供给评分器，不提供给回答模型。评分器从参考原文提取必要要点；尚没有人工逐题确认的标准答案。

## 指标口径

| 指标 | 定义 |
| --- | --- |
| 有答案题流程交付率 | 返回合法答案的题数 / 70；仅说明流程成功，不等于正确 |
| 正确完整交付率（辅助评分） | 判断正确且覆盖全部必要要点的题数 / 70；报错、拒答、缺要点均不算成功 |
| 正确拒答率（辅助评分） | 对资料不足问题作出恰当的不足说明或澄清，且没有捏造事实的题数 / 10；运行异常不算正确拒答 |
| 引用支持率（辅助评分） | 被实际引文充分支持的结论数 / 成功交付答案中的带引用结论数；结论可以带多个引用，按结论计数 |
| 引用覆盖率 | 有引用的结论数 / 成功交付答案的全部结构化结论数；并非任意自然语言事实的逐句覆盖 |

引用指标是条件指标：未交付的答案不贡献结论，不能独立用于证明用户体验改善。空答案没有引用支持率，不算 100%。评分缺失会单列，并停止输出完整质量百分比；生成失败仍保留在题目分母。

评分使用默认生成模型的另一次独立调用，采用不同提示，不提供组名、内部复核意见或是否批准。两组相同答案只评一次。**这是同模型辅助评分，存在共同偏差，不是独立人工核验。** 评分器只看结构化答案，未单独评估前端固定提示和渲染。

## 复现

先按 [检索评测说明](README.md) 准备语料及 `data/public-campus/test-run.json`，确认本地后端、数据库和 ES 可用。管理员令牌仅存放在忽略目录。

```powershell
python scripts/evaluate_public_answers.py prepare --output data/public-campus/answers-new --tokens data/public-campus/tokens.json
python scripts/evaluate_public_answers.py run --output data/public-campus/answers-new
python scripts/evaluate_public_answers.py summarize --output data/public-campus/answers-new --archive docs/evaluation/public-campus/runs/新的问答运行.json
python -m unittest discover -s scripts -p test_evaluate_public_answers.py
```

`run` 会显式编译测试 CLI 并消耗真实模型额度，普通单元测试不联网。结果拒绝覆盖。中断不自动重跑生成；已生成答案和失败记录应保留。

`data/public-campus/answers-new/` 保存冻结输入、逐题答案和诊断、模型信息、统计和 `人工复核.md`；本地原始正文不进入 Git。归档保存问题、结论文本、辅助评审、计数及原始文件摘要，不包含模型密钥。

如发现的是评分器实现错误，可修复后使用 `judge` 命令对既有答案重评。它写入独立 `judgments.jsonl`，保留原评分和生成结果，不覆盖或重生成答案。报告必须说明修复原因，不能因为得分不满意反复评到通过。

## 首轮结果与后续

详见 [80题实测报告](runs/2026-11-24-answers.md) 和 [逐题归档](runs/2026-11-24-answers.json)。本轮未发现复核提高正确交付率的证据，不能写“引用正确率提升”或“问答准确率提升”。

当前适合简历的过程描述：

> 构建 80 条问答评测用例，对比同一初稿在语义复核与定向修订前后的交付表现，建立正确交付、引用支持及无答案拒答的评测与逐题诊断流程。

效果数字暂不建议投递使用。先人工复核失败样本，区分漏答、正确拦截与误拒；尤其检查资料不足状态与复核要求之间的冲突。若据本轮失败调优，本题集就成为回归集，后续效果声明应增加独立测试题。
