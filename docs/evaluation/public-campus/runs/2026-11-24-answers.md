# 公开制度问答生成核验首轮对照

## 结论

80 题全部执行完毕，语义复核及修订没有带来本轮正确交付率提升。存在疑似误拒，不能从“复核通过”推导答案更正确，也不建议把本轮 100% 引用辅助评分直接写进简历。

## 条件

- 70 条有答案题、10 条资料不足题，来自已有公开制度测试集及预留负例。
- 真实 RRF 前 10 个 chunk 冻结回放，不运行在线多跳或历史上下文。
- 生成模型与辅助评分模型均为当时默认的 `deepseek-flash`，配置 ID 9。
- 两组共用同一初稿和引用结构校验，完整组额外做语义复核和最多一次修订。
- 一轮实验，离线工作线程 3；未改变线上参数，未重跑生成挑选成绩。
- 运行源码基点 `99707eb` 加本轮测试工具；输入、实现、原始输出和提示摘要在 JSON 及本地环境文件中记录。

## 全量统计

| 指标 | 初稿+结构校验 | 增加语义复核及修订 |
| --- | ---: | ---: |

| 正确完整交付，模型辅助评分 | 62/70（88.57%） | 58/70（82.86%） |

| 引用支持，模型辅助评分 | 200/200（100%） | 165/165（100%） |
| 结构化结论引用覆盖 | 200/200（100%） | 165/165（100%） |
| 未交付合计 | 6/80 | 17/80 |
| 最终辅助评分调用/协议失败 | 0 | 0 |

正确完整交付逐题配对：58 题两组均正确，8 题均未正确交付，4 题初稿被判正确而完整组未交付，没有从不正确变为正确交付的题目。这里“未正确交付”包括运行失败，不代表每题生成内容都是错误的。

共 16 题进入修订。完整组 17 次未交付按错误码分类：结构校验 6，复核不完整 5，复核状态错误 2，复核无据结论 1，草案调用失败 1，复核调用失败 1，协议无效 1。不能把这些失败全部称为模型幻觉或全部称为正确安全拦截。

## 典型案例抽查

- `q043`：问因病转学的医疗证明。初稿已列指定医院检查证明、诊断专用章、原始病历，并单独说明高考分数条件。内部复核仍以首条结论没写分数条件要求修订，末轮又要求展开用户未问的所有不得转学情形。这是“逐条局部检查”和“整份答案回应问题”之间的疑似误拒，需人工确认。
- `n03`：问宿舍关门时间。冻结资料只含住宿制度原则，初稿状态为 `INSUFFICIENT_EVIDENCE`，没有捏造时间；内部复核却要求明确解释缺失的具体时间，修订后仍因“不完整”拦截。生产渲染会为该状态加上“现有证据不足以完整回答问题。”，表明结构化状态与复核期望的解释文本可能衔接不一致。
- `n08`：问“我所在专业”最低毕业学分。资料没有该专业培养方案的具体数值，初稿追问专业、年级；内部复核认为不应澄清，后续协议失败。该题可接受澄清或说明资料不足，不能要求模型给出没有依据的学分数。
- `q035`：有关停开必修课重修。内部复核指出年级、补考资格及复学情形的条件差异，辅助评分却判初稿完整正确。这里不能直接宣布内部复核误杀，必须检查实际问题范围与全部证据。
- `q071`：辅助评分理由本身出现“已经给出否定结论”与“未明确说明不能再次转换”的矛盾。这说明辅助评分不能直接充当人工标准。

抽查由开发助手完成，尚无独立人工复核；不修改原评分来美化结果。完整原文、引文、内部复核意见保存在本地 `data/public-campus/answers-initial/人工复核.md`、`dataset.json` 与 `calls.jsonl`。

## 评分器修复记录

首次评分提示使用 `claims[0]`，程序期望 `claims/0`，导致有结论的评分被判为协议失败。修正为与生产路径一致，并显式传入路径清单后，只对已保存答案重新评分；生成记录 `calls.jsonl` 保留，修复评分写入 `judgments.jsonl`，二者摘要分别归档。原评分未计入最终质量指标，未重跑生成或替换失败答案。

## 解释边界

1. 只有 23 份制度、91 个 chunk，问题由原文辅助构造，标注及评分尚未人工确认。
2. 生成与评分使用同模型，有共享偏差。引用支持 100% 仅说明这次评分没识别出不支持的结论；不是已经证明没有幻觉。
3. 引用支持只看成功交付答案。完整组少交付 11 题，同时少计 35 条结论，不能把条件引用指标当成整体用户收益。
4. 资料不足题只有 10 道，40% 是 4/10，不能推广到任意真实知识库。
5. 本轮没有在线多跳、上下文和实时资格变化，记录的耗时不是端到端响应延迟。没有独立人类金标准，不提供“人工准确率”。
