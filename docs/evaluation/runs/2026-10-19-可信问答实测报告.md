## 结论与交付范围

最终代码完整执行 15 题，12 题通过自动检查，2 题技术失败，1 题状态不符。它没有超过原服务首轮的 13/15，不能宣称本轮提高了回答准确率。本轮交付的是可重复运行的评测脚本、失败阶段分类、真实结果与问题记录；没有采用未经验证的提示词改进。

最终两个技术失败分别是 B06 的 `KNOWLEDGE_REVIEW_REJECTED` 和 C02 的 `KNOWLEDGE_CITATION_INVALID`，不是两题都被语义复核否决。B08 缺地区时直接返回证据不足，没有按题集要求追问。C01 虽然自动通过，但助手审阅发现部分结论的引文覆盖不足，因此 **12/15 不是语义准确率**。

原服务、三个未采用的提示实验、定向诊断和最终代码的逐题记录均保留在 [脱敏数据](2026-10-19-results.json)。其中包含成功答案、实际候选原文、文档状态、失败码、耗时、可获得的 Token 与运行摘要。审阅者是开发助手；没有独立人类标注，也不提供“人工金标准准确率”。

## 环境与方法

- 测试日期：2026-10-19，业务时间为 Asia/Shanghai。资料有效窗口为 2026-10-01 至 2027-01-01 之前。
- 真实本地 HTTP 服务、MySQL、Elasticsearch 和配置的模型服务；没有使用模型桩代替本表成绩。
- 回答模型配置名称：`deepseek-v4.1-flash`；Embedding 配置名称：`qwen3.7-text-embedding`，1024 维。这里只记录项目配置返回的名称，不证明厂商实际路由版本。
- 检索参数沿用原默认库：候选 50、向量最低相似度 0.0、最终结果 5。阈值为 0 会召回与金额问题不相关的通用流程，这是当前环境的一部分，未为了得分调参。
- 固定题集为 15 题，SHA-256 为 `f3f8d935ac65e1530ce065c8a24c8b46067dd28fd0ba833045df354f200d9e93`。每题新会话、一次生成；没有对失败题自动重试，也没有在同一轮删除失败题。
- 七份资料来自仓库原创的虚构制度。完整运行创建专用库，按正常、冲突、撤回冲突、撤回当前标准的顺序切换场景；旧版、未来版、草稿和其他地区资料用于检验准入隔离。
- 请求失败、协议不合格、引文不合法、复核否决都记为技术失败，不记为正确拒答。正常返回不足状态与技术失败分别统计。
- 题集已经用于开发和提示实验，是开发回归集，不是独立盲测集。不同轮次只有一次完整运行，含模型随机性；不做统计显著性或因果改进结论。

### 自动通过仍可能存在引用覆盖缺口

最终 C01 的总结说“两份同时有效且同样适用的制度给出不同金额”，对应 quote 却只有冲突通知中的条件句：“若另一份同时有效、同样适用的制度写明不同金额，应由知识维护者核实。”该句本身没有证明另一份文件实际存在或给出了不同金额。完整候选中确有另一份 600 元文件，因此应区分“整轮证据可支持冲突”和“该条结论的引用完整支持断言”。

同题冲突双方的 text 写出了“超过上限由个人承担”与“超出不予报销”，但各自 quote 只截取金额句。完整 Chunk 里确有这些规则，故不是凭空编造，仍不满足严格的结论到引文覆盖要求。原服务基线也出现过类似问题。逐字子串校验和同一模型的另一次复核都未能保证语义覆盖。

### 复核同时存在有效拦截和误杀

定向诊断 `diagnostic-01` 使用既有的临时模型协议日志，只针对虚构资料。脱敏交互保存在数据文件的 `diagnosticExchanges`，默认运行的日志仍关闭。

- B04/B05 的草案明确写出上海每晚 600 元、超出上限不予报销，quote 也完整包含两句；复核却给出 `UNSUPPORTED_CLAIM`。助手对照原文判断这两个样本为复核误杀。
- R01 在同一轮对相近的金额和超额规则通过复核，提示判定存在不稳定性；问题措辞和上下文不同，不能把这当成严格对照实验。
- W01 已撤回当前标准，仅剩通用资料；草案要求用户选择制度版本，复核以 `UNNECESSARY_CLARIFICATION` 阻断。这里应报告缺资料，而不是把版本裁决交给用户。
- B06 的否决不能仅凭错误原因认定误杀。模型提供的原因是待审阅线索，不是事实标签。

## 最终代码为何回退全部提示

实验一、实验二尝试区分缺条件与缺资料、避免无关流程和过宽的冲突表述。实验未得到更好的完整轮表现。随后只增加原因枚举提示的一轮也降到 8/15，说明输出协议的提示改动也可能影响模型决策，不能当作没有行为影响的纯日志改造。

最终 `RULES`、`DRAFT_PROMPT`、`REVIEW_PROMPT` 三个常量与原提交 `182fa74608f5cb2c180ad7db3d5fe4de8c20398b` 的内容逐字核对一致。保留阶段异常与历史消息错误码；解析器兼容可选原因枚举，但默认仍只要求 `approved` 布尔值。最终源码摘要和 JAR 摘要见逐题数据，其中 JAR SHA-256 为：

`56BF3E487AB8C088D12A4F28AF5440ECFC2253197043CCB2166A4E2E6E7BB14E`

原服务首轮没有记录运行 JAR/源码摘要，归档中为 null，不能事后补造；后续轮次记录实际启动的 JAR 摘要。本地 Git commit + dirty 只描述工作区起点，不能单独证明运行版本。实验未全部保留完整源码快照，因此这些失败实验的严格重现仍有限制；最终提交代码、固定题集及资料则可以重新运行。数据中的 `offlineAudit` 是最终检查器对已有报告的离线补充核验，不是重新调用模型，也不修改原始 outcome。
