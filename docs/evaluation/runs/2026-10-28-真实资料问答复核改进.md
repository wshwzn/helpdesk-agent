# 真实资料问答复核与一次修订验证

## 问题与改动

用户在知识库“项目开发记录”询问“项目是否具有澄清机制”时，实际检索已包含明确依据，仍经常在复核处整条失败。原始运行及四条同题对照见[只读诊断](2026-10-28-开发记录澄清问答失败诊断.md)。本轮保留充分解释，不修改用户的检索结果数量、相似度、知识资料或默认模型。

改动是：围绕所问事项、必要条件及历史阶段做复核，要求具体缺陷；首次具体否决后，用相同证据目录修订一次，重新执行引用、结构、范围/检索上下文和语义校验；末次仍否决则失败。部分可答和冲突展示可以成为最终结果，但都必须通过复核。诊断保存两轮草案与判断，费用完整累计。

## 固定对照方法

- 默认文本模型始终为配置9“dp官方”，modelName=deepseek-flash。未换模型。
- [冻结题集](../knowledge-recovery-cases.json)取两个既有真实问题：“项目是否具有澄清机制”“这个项目的问答链路是怎样的”。原运行分别为 f4fb67fb-789a-4dca-ad43-5ab8e28e78f8、0e25916d-9dd4-426d-8eef-107d7213f570。
- 保留各自完整50条原始证据及顺序。生成和复核真实调用模型，检索和交付资格依赖固定，因此这是生成到核验的回放，不是在线端到端测试。
- 每题每策略事前固定两次，第二次交换 BASELINE/GROUNDED 顺序；所有结果保留，失败不重跑择优。
- 另外使用六份固定草案：两个基于真实开发资料的错误断言，既有错误金额、遗漏冲突、提示注入反例，以及一个部分可答正例。它们全部先通过结构/引用检查，测试语义判断；每策略每份一次。
- 阈值提前写入题集：真实问题通过数提高，错误草案被拦截、部分可答正例通过；人工核对答案，不能仅用返回成功代替正确性。人工判断由开发助手完成，不是独立人工金标准。
- 原始结果、源码和规则摘要、耗时与用量见[回放数据](2026-10-28-真实资料问答修订回放数据.json)。

“问答链路”第一次 GROUNDED 复核指出三处问题：缺范围被写成一律追问、续答字段只写单范围、阶段枚举遗漏适用性与规划。修订保留完整流程并补充历史阶段语境、多范围续答、APPLICABILITY/PLANNING，第二次复核通过。第二次独立回放首次通过。复核意见仍可能过严或有误，不应把模型解释直接当作事实。

人工阅读四份候选答案的流程主干、引用及修订内容，与所引资料相符。开发记录同时描述多个阶段，个别说明仍沿用旧参数措辞；本轮不宣称所有历史细节已经完美消歧或没有语义漏检。

两策略共30次实际模型调用，已知文本Token合计854499，全部有用量；不含检索、规划或Embedding，因为这些依赖在本次回放中固定。复杂问题触发修订的一次耗时266.2秒，其余GROUNDED为65.5、41.7、75.0秒；BASELINE为91.4、82.0、191.0、129.2秒。小样本无法据此声称稳定延迟提升，修订路径最多增加两次调用。
