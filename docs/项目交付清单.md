## 明确保留的限制

- 回答质量：只检查召回资料，可能过早停止并漏冲突；同模型复核可能误拒、漏检。E05正确金额和差额草案被拒，未交付，不算正确业务拒答。阶段45改善已有真实问题的核验通过情况，但K03仍出现把历史工具流程当成当前流程的错误，具体缺陷复核与一次修订未消除全部语义风险。
- 可靠性：至少一次索引可能重复计费；过期 ES 批次、OSS 孤儿及上传中断恢复不完整；真实多实例故障演练未完成，不能宣称生产高可用。
- 一致性：MySQL/ES/OSS 没有分布式事务；多次资格校验不等于全局原子快照。
- 来源：同 Bucket 登记目录、单向、文档级轮询；默认每次最多 200 个对象，不捕获轮询间覆盖的全部中间版本；缺失不自动撤回。
- 对话：最多三范围，依赖配置名称识别；澄清是显式流程，非任意多轮长期记忆。默认库全局共享，scope 非权限隔离。
- 验证：小型开发题集、虚构资料、本地联调；未做容量压测、完整独立人工金标准或真实生产部署验证。外部前端不在本仓库，未宣称本轮实现前端多选控件。

## 当前没有实现

原生 Tool Calling、MCP、多 Agent、多租户/复杂文档 ACL、知识反馈闭环、多种连接器、双向文档编辑、段落级增量向量化、全库冲突扫描。旧客服工具代码保留用于历史兼容，不属于当前问答主线能力。

当前源码默认：多跳开启、候选 task-planning 关闭、GROUNDED 审核与最多一次修订。运行进程需加载新版本配置才能生效。“dp官方”保持默认；未因本轮失败切换模型或扩大调优范围。

## 交接入口

1. 先读[架构说明](architecture/企业知识问答架构.md)，理解两个完整流程和事务边界。
2. 按[代码阅读与动手练习](interview/代码阅读与动手练习.md)跟一条真实运行，解释已知失败。
3. 从[简历描述与能力边界](interview/简历描述与能力边界.md)选择自己已理解的内容。
4. 用[口述准备](interview/可信知识问答口述准备.md)练一分钟介绍和追问。
