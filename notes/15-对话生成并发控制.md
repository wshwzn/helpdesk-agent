# 同一对话生成并发控制

## 实现功能与业务规则

- 同一对话同一时间只允许生成一条 AI 回复。
- 创建一轮消息前，事务会检查是否存在 `PENDING` 状态的助手消息。
- 如果上一条回复仍在生成，接口返回 HTTP 409，错误码为 `CONVERSATION_GENERATION_IN_PROGRESS`。
- 被拒绝的请求不会保存客户消息，也不会调用大模型；上一条生成任务不受影响。
- 两个请求在准备消息阶段同时进入时，继续由 `conversations.version` 乐观锁保证只有一个事务成功，失败事务会连同刚插入的消息一起回滚。
- 第一个事务已经提交、AI 仍在生成时，由 `PENDING` 检查拒绝后续请求；两种机制共同覆盖完整的生成周期。
- 客户再次发送前会先检查并回收超过阈值的 `PENDING` 助手消息，默认阈值为 10 分钟；未超时任务仍返回原有 409 冲突。
- 后台任务默认每分钟扫描一次全局遗留消息，即使客户没有再次发送，也会把中断任务恢复为 `FAILED / GENERATION_INTERRUPTED`。
- 回收使用消息状态、更新时间条件和版本号递增，防止正常完成或迟到的模型结果覆盖恢复状态。
- 中断回答关联的 `RUNNING` 工具调用会转为 `FAILED`，尚未确认的工单草稿会转为 `INVALIDATED`。

## 新增文件

- `ConversationGenerationInProgressException.java`：表示同一对话已有正在生成的 AI 回复。
- `StaleChatGenerationRecoveryService.java`：条件回收超时消息，并清理工具调用和待确认操作状态。
- `StaleChatGenerationRecoveryJob.java`：按照配置间隔执行全局兜底扫描。
- `V15__add_chat_pending_recovery_index.sql`：为状态、角色、更新时间扫描增加联合索引。
- `15-对话生成并发控制.md`：记录本次并发控制规则和验证结果。

## 修改文件

- `ConversationPersistenceService.java`：准备消息时拒绝已有待生成消息的对话，并沿用原有乐观锁处理瞬时并发。
- `ChatProperties.java`、`ConversationConfiguration.java`：增加中断阈值、扫描间隔配置和定时任务能力。
- `GlobalExceptionHandler.java`：将生成中冲突转换为明确的 409 响应。
- `ConversationControllerIntegrationTest.java`：覆盖生成期间重复发送的拒绝行为，以及过期消息、工具记录和工单草稿的自动恢复。
- `application.yaml`、`.env.example`、`README.md`：公布恢复参数和运行规则。
- `docs/database-schema.md`：记录新增索引以及 `GENERATION_INTERRUPTED` 错误码语义。

## API 与数据库变化

- 对话发送接口路径和请求体不变。
- 新增冲突错误码 `CONVERSATION_GENERATION_IN_PROGRESS`。
- 没有新增或修改字段；Flyway V15 增加 `idx_chat_messages_status_role_updated` 联合索引。
- 不使用等待式或 `NOWAIT` 行锁，避免与已有乐观锁重复实现同一层并发控制。
- 新增 `CHAT_PENDING_TIMEOUT` 和 `CHAT_PENDING_RECOVERY_INTERVAL` 环境参数，默认分别为 `10m` 和 `1m`；前者必须大于 `APP_CHAT_STREAM_TIMEOUT`。

## 已知限制与后续工作

- 当前使用 `updated_at` 判断生成是否过期，没有单独维护生成心跳；因此模型请求的最大执行时间必须始终小于回收阈值。
- 当前后端保证并发安全，前端仍可进一步在收到该错误码时显示“AI 正在回复，请稍候”。
