# 后端服务器部署

## 实现功能与规则

- 在服务器独立运行后端、MySQL 和 Elasticsearch，以空库开始，Flyway 自动初始化业务表。
- 组件使用项目专用 Docker 网络，数据库不映射公网端口；后端仅监听宿主机 `127.0.0.1:8080`，由前端站点的 OpenResty 转发 `/api/`。
- 服务器生成独立的数据库密码、JWT 密钥与模型加密密钥；OSS 使用现有配置，凭据不进入仓库。
- 限制各容器内存并开启自动重启、健康检查与日志轮转，适配当前小内存服务器。
- 初始化管理员 `admin` 与客户 `user` 两个演示账号，知识库和模型配置保持为空。
- ES 初始占用接近 1 GB，容器上限调整为 1280 MB；堆保持 512 MB，为非堆和索引操作保留余量。

## 新增与修改文件

- `application-prod.yml`：生产数据库、文件存储、ES、连接池和上传配置。
- `deploy/compose.yaml`：定义三个容器、持久化目录、网络、健康检查和资源限制。
- `deploy/.env.example`：不含真实凭据的生产变量模板。
- `deploy/openresty-api.conf.example`：供两个前端站点复用的 API 与 SSE 转发配置。
- `deploy/backup.sh`：手动备份 MySQL 及配套应用密钥。
- `deploy/README.md`：启动、更新、备份与前端接入说明。
- `pom.xml`：JAR 打包时排除本地私有配置，保留本地开发运行方式。
- `README.md`：增加部署文档入口。

## API 与数据库

- 无业务 API 或表结构变更；服务器使用已有 Flyway 迁移初始化空库。

## 验证

- `mvn clean verify`：77 项测试通过；重新打包并检查 JAR，确认包含生产配置且排除本地私有配置。
- 上传后的 JAR SHA-256 与本地一致，三个容器健康检查通过；MySQL 8.0.46、ES 9.5.4，全部 15 个 Flyway 迁移成功。
- 演示账号登录成功，客户访问管理接口返回 `403`。
- 通过后端 API 验证 OSS 上传、原文下载、Tika 分块预览及文档删除。
- 使用临时索引验证 ES BM25 和 dense_vector KNN；测试索引、文档、知识库已清理。
- MySQL 和配套应用密钥首次手动备份成功，并下载至本地 Git 忽略的 `data/deployment/` 目录。

## 限制

- 单服务器单节点部署，没有高可用；仅提供手动备份脚本。
- 前端由用户自行部署并配置 OpenResty；默认 Chat 与 Embedding 需在空库重新配置。
