# 文档版本与检索准入

## 实现行为与业务规则

- 文档新增稳定来源、业务版本、单一适用范围、生效及失效时间、独立发布状态。原 `version` 仍为乐观锁，原 `status` 仍为处理状态。
- 业务发布流程为 `DRAFT → PUBLISHED → WITHDRAWN`。配置草稿元数据后回到 `PENDING`，重新索引至 `READY` 才能发布；发布后的内容与元数据不可直接修改，修订需另行上传。
- 范围 `ALL` 表示通用业务资料，不是权限。省略范围只查 ALL；明确范围则查该范围和 ALL。范围不由文件名或上传时间推断。
- 有效时间统一为 Asia/Shanghai，区间左闭右开；未来文档可提前发布但不会提前参与召回。多个同时有效的版本保留双方，不按版本标签自动裁决。
- MySQL 作为检索准入权威，在 BM25 与 KNN 召回前传入可用文档 ID，并在返回后复核撤回和到期；无有效文档时不调用向量模型或 ES。超过 10000 份准入文档明确失败，不静默截断。
- ES Chunk 保存不可变业务元数据快照，映射通过增量 PUT 扩展；可变发布状态不在 ES 重复维护，避免撤回依赖跨存储同步成功。
- 工具结果和引用增加文档 ID 及业务元数据；同名不同文档不会去重合并，旧工具 JSON 仍能解析。引用仍只是检索来源，不证明回答结论已经被验证。
- 已发布文档须先撤回再删除；当前非原子索引替换限制在草稿，不宣称已实现可靠增量更新。

- `KnowledgeDocumentPublicationIntegrationTest`、`KnowledgeCitationServiceTest`：业务准入、API、历史升级及引用兼容性验证。

## API 与数据库变化

- 新增文档 `PUT .../metadata`、`POST .../publish`、`POST .../withdraw`，均限定 ADMIN；发布和撤回请求为 `{"version": 当前乐观锁版本}`。
- 搜索请求新增可选 `applicabilityScope`。文档、搜索结果、知识工具结果和消息引用返回业务元数据。
- V16 新增 6 个字段、1 个联合唯一约束、2 个检查约束及准入联合索引，详见 `docs/database-schema.md`。
- **升级注意：历史 READY 文档保持原处理状态，但迁移为 DRAFT，必须补元数据、重新索引并发布才恢复正式召回。** 原始对象与已有 ES 片段不会被迁移删除。
- 新旧接口的上传路径和文件字段不变，但“索引完成即可检索”已改为必须显式发布，管理端需要接入发布流程。

## 已知限制与后续工作

- 当前使用 MySQL 文档 ID 白名单，适合单企业小规模知识库；单次超过 10000 份有效文档明确报错。后续扩大规模需要评估 ES 投影同步方案与查询成本。
- 复核只能保证检索返回前观察到的有效性；生成回答期间仍可能发生撤回，下一阶段需要在答案核验时再处理证据有效性。历史消息保留当时快照。
- 已发布元数据固定，当前无自动替代关系。预设有效期可在边界交接；没有预设截止的旧版需手动撤回。撤回是终态。
- 单范围不构成用户权限；无范围词典、多条件适用规则、可靠自然语言映射或前端界面。
- 原检索评测未增加范围/时间字段，仍仅评测 ALL 通用资料；不在本轮宣称答案正确率、冲突识别率或拒答率。
- 未实现正文冲突核验、强制逐结论证据校验、可靠增量来源扫描、索引批次切换及失败保留上一批次。
