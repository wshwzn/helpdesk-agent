# 片段选择与原文引用

## 设计与业务规则

上一轮 B05 的结论金额正确，但模型抄写 quote 时删掉了 `600` 两侧空格，导致逐字引用校验失败。本轮由模型选择片段、后端提取原文；不放宽原来的逐字校验，也不把真实出处等同于语义正确。

- 每轮检索完成后建立独立 UUID `citationSetId`。每份 E 编号证据按空行分段，编号如 `E1-P1`；单换行、空格、数字、单位、否定原样保留。偏移是 Java UTF-16 下标，区间左闭右开。
- 不把超过 1500 字的段落强行切断。过长、少于 4 个去除首尾空白后的字符、含保留引用标签的段落保留上下文但 `selectable=false`。模型仍须考虑其限制和相反依据；无法引用充分依据时用证据不足状态。
- 模型协议只允许 `citationSetId` 与每条引用的 `evidenceId + paragraphId`，禁止 quote。程序验证目录身份、证据归属、片段存在与可选性后，从本轮原文 substring 提取完整段落，再执行原状态/结构/逐字校验。
- 目录不匹配（含跨轮）、跨证据片段、未知或不可选片段均为 `KNOWLEDGE_CITATION_INVALID`；旧自由引文或额外 quote 字段为 `KNOWLEDGE_PROTOCOL_INVALID`。引用最多仍为每项 5 个，结论和冲突数量限制保持原样。
- 复核仍读取全部候选原文及已解析草案，复核规则保持原样。数字误读、否定颠倒、范围扩大并不能靠片段校验发现，仍依赖模型复核；复核具有误杀和漏检风险。
- 新管理员诊断 `schemaVersion=2`：`citationCatalog` 保存目录，`selection` 保存模型原始选择（包括失败选择），`draft` 在完成引用解析与结构校验后保存。取消后迟到选择不能覆盖终态。

## 新增文件与职责

- `KnowledgeAnswerSelection`：与客户回答隔离的模型选择协议，不含引文内容字段。
- `KnowledgeCitationCatalog`：每轮目录、证据元数据、完整段落与偏移，生成可引用标记。
- `KnowledgeCitationCatalogTest`：段落边界、跨轮/跨来源身份、原文一致性、长度和缺字段约束。

## 修改文件与职责

- `KnowledgeAnswerModelClient`：只调整草案输入/输出协议；生成输入只提供分段正文，不重复发送完整正文。共用规则与复核提示保持原文。
- `KnowledgeAnswerGuard`：解析片段并提取原文，继续调用原确定性校验。
- `TrustedKnowledgeAnswerService`：检索阶段建立目录，生成阶段采集选择，校验阶段提取原文，再复核和复查准入。
- `KnowledgeAnswerTrace`、`KnowledgeAnswerRunSnapshot`：保存新版目录和选择，旧快照缺失字段按 null 读取。
- 三个既有问答测试类：适配模型选择桩，覆盖真实协议、复核否决、诊断持久化、旧版本读取和取消。

## API 与数据库

客户消息和 `KnowledgeAnswerReport.schemaVersion=1` 保持原结构，引用仍是 `evidenceId + quote`；历史回答无需迁移。管理员详情新增上述字段，列表不返回草案。数据库表和列没有变化，不新增 Flyway；数据库字典同步 JSON 版本语义。

## 测试与实际验证

- 全量 `mvn -B test package`：155 个 Java 测试通过；Python 工具测试 13 个通过。最初定向运行曾因 Mockito 覆盖桩触发旧 Answer（传入 null 目录）失败，已改用 doAnswer/doThrow 正确覆盖；随后全量通过。
- 真实固定 15 题：10 个自动通过、4 个复核否决、1 个缺地区状态检查失败。上一轮 12/15，本轮不宣称整体准确率提升。
- 15/15 通过引用解析，B05 由上轮空格改写失败变为本次成功；15/15 新版诊断完整，含失败草案共 29 个引用均经离线比对，严格匹配所选段落与原文偏移。
- 已知回答 Token 从上轮 25708 增至 31765（含失败，不含 Embedding），调用从 29 次变为 30 次；完整段落和目录有成本，不能只展示引用通过率。语义负例以复核桩验证阻断流程，不冒充真实模型检出率。
- 真实 HTTP 检查旧版本 1 诊断仍可读取、新管理员诊断拒绝客户；全量集成测试覆盖取消、诊断写入故障与旧报告读取。
- 默认库恢复 7，文档、模型、检索配置核对一致；默认切换正常增加 version/updatedAt。专用评测库 15 保留，临时 8081 与凭据文件已清理，原 8080 需重启才能使用新代码。
- 详见 `docs/evaluation/runs/2026-10-19-片段引用验证.md` 与对应数据文件，保留所有失败和助手语义审阅发现。

## 已知限制与后续

空行不等于业务语义边界，条件可能跨段或已在检索 Chunk 外丢失；通过完整候选复核缓解，不能彻底解决。较长引用可能增加复核 Token 与诊断体积；不增加重试或隐藏技术失败。缺地区追问、复核误杀属于后续独立改进。
