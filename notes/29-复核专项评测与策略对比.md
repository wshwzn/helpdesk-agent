# 复核专项评测与策略对比

## 设计与业务规则

本轮固定问题、证据与草案，隔离检索和生成波动，分别观察正确草案被否决（误杀）与错误草案被批准（漏检）。技术失败单列，不把调用失败算成成功拦截。

- 冻结 12 组共 24 题正反例，每组问题与证据相同，分别给出正确与错误草案；全部先通过结构及逐字引用校验，测量语义而非格式边界。标签由开发助手拟定，附依据，未冒充独立人类金标准。
- 16 题 DEVELOPMENT、8 题 CHALLENGE 同时冻结；后者采用新领域资料，但仍由同一助手编写，不能当独立盲测。每种策略运行两轮，每轮固定种子打乱题序，交替先调用哪一种策略。
- BASELINE 保持原布尔提示；CHECKLIST 为显式实验策略，逐条检查结论支持和条件保留，再判断状态、完整性、冲突与追问。只允许 PASS/FAIL/UNCERTAIN，服务端确保每个结论路径恰好覆盖一次，全部 PASS 才批准。
- 检查表缺项、重复、未知路径或非法枚举是协议失败；UNCERTAIN 拒绝放行。检查表结论仍来自模型，程序只保证协议完整与汇总，不保证语义判断正确。
- 事前采用门槛写在题集：两轮误杀均降低，漏检与技术失败均不增加，CHALLENGE 不退化，才考虑候选端到端验证。端到端不得增加错误放行、自动通过数不得低于同轮基线。默认仍为 BASELINE，最终决策以真实结果补充。

## 新增文件与职责

- `KnowledgeReviewChecklist`：逐项复核结构、结论路径与后端汇总。
- `knowledge-review-cases.json`：固定成对草案、预期判断、标注依据及事前决策门槛。
- `KnowledgeReviewEvaluationCli`（测试目录）：只启动读取模型配置所需组件，不启动 Web、Flyway、业务调度或检索；逐调用保存结果、提示摘要与用量。
- `evaluate_knowledge_review.py`：显式构建运行器、保留中途结果、统计误杀/漏检/技术失败/跨轮翻转，评估是否达到门槛。
- `KnowledgeReviewChecklistTest`：覆盖检查表、汇总、失败用量、旧结构、默认策略与标签隔离。
- `test_evaluate_knowledge_review.py`：技术失败计数、身份去重、漏题、两轮门槛及稳定性测试。
- `docs/evaluation/knowledge-review.md`：运行命令、标注、指标口径和采用流程。
- `docs/evaluation/runs/2026-10-19-复核专项对比.md` 及两份 JSON：全部专项结果与默认策略端到端归档。

## 修改文件与职责

- `KnowledgeAnswerModelClient`：保留基线提示，增加检查表策略入口；原复核结构新增可空 checklist，旧诊断可继续读取。检查表协议失败保留已知用量。
- README、评测总说明：增加专项入口与本轮实验决策；数据库字典补充可空 checklist 的 JSON 语义。

## API 与数据库

没有新增 HTTP 接口或数据库表列，无 Flyway 变更。`app.knowledge.review-strategy` 可显式设为 BASELINE 或 CHECKLIST；默认 BASELINE。管理员诊断的 `review.checklist` 为新增可空内容，仅检查表策略有值，客户接口不返回检查表。

## 测试与手动验证

- 全量 Java 164 个测试、Python 18 个测试通过；普通测试不调用真实模型。
- 专项 96 次调用：BASELINE 正例误杀 0/24、负例漏检 2/24、技术失败 0；CHECKLIST 正例误杀 2/24、负例漏检 2/24、技术失败 1。已知 Token 分别 29732、44854，候选约多 50.9%。
- 门槛未满足，**保留默认 BASELINE，CHECKLIST 仅为显式实验策略**。未重跑挑选高分，没有继续候选端到端。
- 保留基线的原 15 题回归：13 自动通过、2 次复核否决，15/15 诊断完整。提示不变，不把比上轮 10/15 高的结果归因于新策略。
- 全部专项结果与摘要离线核对一致、题集未变；历史版本 1 诊断经真实 HTTP 读取，新字段为空。
- 默认库恢复 7，原资料、模型及检索配置一致；默认切换使 version 正常增至 10。专用库 16 保留，临时服务与身份文件已清理。

仅显式运行专项脚本才调用真实模型。运行器不重试失败项，底层客户端沿用项目配置，应用层调用数不证明实际 HTTP 请求数。详见实测报告。

## 已知限制与后续

固定小样本由开发助手标注，两轮仅观察初步稳定性，不提供泛化准确率或统计显著性保证。本集为重写的成对草案，未原样回放全部历史失败，不能据基线零误杀推断端到端没有误杀。候选实际增加成本、协议失败和误杀，故未替换默认策略。下一步优先追加版本化的真实失败回放集。
