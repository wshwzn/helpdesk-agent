# 31-练习环境与真实失败复核

## 目标与业务规则

用户明确面试主要是口头交流，本轮不建设展示页面。建立可重复使用的练习环境，让用户能够自己复现并解释；另以历史失败输入做复核实验，最终只按真实结果形成可讲述的取舍。

- `prepare_knowledge_practice.py` 正常注册专用 CUSTOMER，密码随机生成并仅保存于忽略目录；创建脚本拥有的练习库，配置范围澄清。默认不切换全局库，显式 --activate 且全部准备成功才切换。
- 重复执行复用原账号、库、就绪文档和配置；已完成资料的内容、业务元数据或发布状态变化会停止，不自动恢复已撤回资料。未知文档、身份或环境不符也停止。
- 七份资料保留正常初始状态：前五份发布，未审核版和冲突通知为草稿；有效期过滤旧版/未来版。正文与元数据一致，有效窗口仍为 2026-10-01 至 2027-01-01 之前。
- 练习库不承载自动撤回测试。评测库独立，脚本结束恢复原默认库；所有客户仍共享全局默认库，账号不是多租户隔离。
- 真实复核集保留原 24 题，追加 B03/B09 原样问题、范围、候选证据和草案，以及各一个错误金额/错误状态反例，共 28 题。来源和摘要单独保存在 provenance 文件，原始历史报告不修改。
- CONTEXTUAL 候选在原复核规则后补充上下文理解：允许结合问题和显式范围限定结论，允许证据不足状态只回答有据部分；明确扩大范围、错误事实、ANSWERABLE 遗漏实质问题仍需否决。保持布尔协议，不新增自由文本理由。
- BASELINE、CHECKLIST 原提示及默认 BASELINE 保持原文。CLI 显式选择 BASELINE 与一个候选比较，避免新增枚举后意外比较三种策略；每种策略两轮，共 112 次调用，不自动重跑。
- 采用门槛仍为每轮误杀严格减少、漏检与技术错误不增、CHALLENGE 不退化，达到后才做候选端到端验证。原样失败重放不是独立人工金标准，也不能假定历史误判必然再次出现。

## 验证记录

完整 Maven 构建 178 项测试通过，Python 27 项通过。真实练习环境已初始化并激活，重复执行复用了相同账号/库；五次练习问答（通用期限、两个地区的澄清与续答）均自动通过，数据和资料状态保持一致。复核实验完成 112 次调用；BASELINE 误杀 6/28、错误放行 3/28，CONTEXTUAL 误杀 4/28、错误放行 3/28，双方技术失败均 0。候选第一轮错误放行增加且 CHALLENGE 退化，Token 增加约 28.8%，未满足事前门槛，默认保留 BASELINE；不继续候选端到端，不重跑挑高分。

## 已知限制

后续讨论已整理为 `docs/企业知识问答后续路线.md`，README 增加入口。该补充仅规划后续优先级和验收：先收敛客服遗留工具，再完成增量更新、受控多跳、统一入口及项目收尾。原始目标文档保留原样；没有在此次文档补充中修改运行行为、API 或数据库，也未新增模型调用。检查了文档链接和 Git 差异，未重复运行代码测试。

- 主题识别和语义复核仍依赖模型，固定小样本不能推出生产正确率。
- 本地 state 文件减少重复写入，但不提供分布式事务或任意崩溃点恰好一次语义；中断在服务端成功/本地状态未保存之间可能需要核对。
- 凭据仅保留在忽略目录，不打印或归档；清理 target 会丢失随机密码和恢复信息，应自行安全保管。
- 全局默认库切换需要避免与其他操作者并发；当前接口没有 CAS 切换协议。
- 不建设多租户、前端展示或新的 Agent 框架；自动增量同步仍未完成。
