# 32-知识助手入口与工具收敛

## 实现目标与业务规则

落实后续路线 A 阶段：项目主线转为企业内部知识问答，客服工单退出问答工具列表。此次不实施增量更新、多跳检索或最终模式统一。

- 新消息请求省略 `mode` 或显式传 `null` 时默认 KNOWLEDGE；仅传正文的内部构造与持久化入口使用相同默认值。显式 KNOWLEDGE 行为不变。
- 默认知识请求省略适用范围时使用 ALL，正文最多 2000 字。条件澄清与续答继续沿用原问题、原知识库及配置修订校验。
- 知识请求强制走原检索、引用解析、语义复核与交付前资格复查；失败不回退普通对话。SSE 先发送 start，核验并保存后才发送完整正文和 done，失败不发送草案正文。
- 显式 AGENT 暂作旧客户端兼容，保留原历史上下文和流式协议，但只注册 `search_knowledge_base`。不再注册 `list_my_tickets`、`get_my_ticket`、`prepare_create_ticket`。
- 旧兼容模式提示改为企业制度、产品资料和流程问答，不引导创建工单、提交反馈或发布撤回。明确该模式没有完整可信核验保证，不能把检索引用当成已核验结论。
- 历史工具回放按照当前注册名单过滤，仅回放关联助手消息上仍可用的知识工具；退出的工单工具、未知工具及不关联的记录不进入模型工具上下文。旧正文和数据库中的原工具记录不删除。
- 工单接口、草稿确认和历史数据继续按原权限、版本及有效期运行；员工继续使用 CUSTOMER 角色代码，未增加角色或改变管理员权限。

## API 与数据库变化

未新增或删除 HTTP 接口，未改变消息响应字段；同一消息接口的默认模式变化是本轮实际兼容变化：

| 请求或历史记录 | 当前行为 |
| --- | --- |
| 省略 mode / mode=null | KNOWLEDGE，默认 ALL，正文上限 2000 字，SSE 核验后发送完整正文 |
| 显式 KNOWLEDGE | 保持原可信问答与澄清续答 |
| 显式 AGENT | 旧模式兼容，正文上限仍为 10000 字，拒绝请求级范围和澄清 ID，仅提供知识检索工具 |
| 历史 AGENT 消息 | 原 mode、正文、引用和工具审计数据保留，不补造核验报告 |

没有数据库 DDL 或 Flyway 迁移。`chat_messages.mode` 的数据库默认值仍为 AGENT，以兼容既有迁移及历史语义；应用显式保存本轮有效模式，新缺省请求写入 KNOWLEDGE。数据库字典对此作出区分。

## 限制与后续

- 显式 AGENT 仍是较弱的兼容路径，提示中的限制不是事实正确性保证；此次不能称为已完成阶段 D 的入口统一。
- 未检查或修改其他前端项目。若调用方仍显式发送 AGENT，不会因为后端默认值改变而自动进入知识模式；应发送 KNOWLEDGE 或省略 mode。
- 旧客户端省略 mode 时会受到 2000 字限制，并且 SSE 不再逐段输出未核验文本，需要按新契约接收。只存在 citations 不能显示可信核验标记，必须结合实际 knowledgeAnswer 报告及状态。
- 工单接口保留意味着人工直接调用仍可执行业务；本轮收敛的是模型工具和知识问答主线，没有实施接口下线或数据删除。
