# 文档提交与可靠索引

## 业务行为与设计

本轮为 B1：先完成内部文档提交后的可靠索引。上传仍得到 PENDING，管理员可先保存元数据、预览分块；新增“保存并提交”原子保存完整业务元数据及索引任务，后台自动执行。READY 仍是草稿，发布必须另行确认。没有任务的 PENDING 文档不会被自动扫描或处理。

文档 PROCESSING 包含排队、执行及自动重试等待；任务表进一步区分 QUEUED / RUNNING / SUCCEEDED / FAILED。每份文档只保存最近一次提交，默认最多执行 3 次；暂时性错误退避 30 秒，解析错误直接失败。任务耗尽后管理员可通过原索引接口重新提交。PROCESSING 期间重复索引请求返回现有状态，不重建任务；元数据提交仍要求正确乐观锁版本，不承诺重复 POST submit 幂等。

调度周期 2 秒，每实例一个任务；线程就绪才竞争领取。数据库时间计算 120 秒租约，调度线程续租；进程停止后其他实例或重启后的实例可接管过期任务。每次领取新 UUID 令牌，ES ID 包含该令牌。数据库激活批次与任务成功在同一事务中提交，过期执行者不能修改状态。BM25/KNN 均只检索 MySQL 选中的有效批次；历史无批次数据只匹配没有 indexBuildId 的旧片段。技术批次不等同于业务版本。

模型、存储与 ES 检查移到后台。请求成功仅表示任务已入库，不表示外部依赖可用或已经完成索引。数据库与 ES 不使用分布式事务：先写隔离批次，再事务提交有效指针；不确定或失败结果保留为不可见残留，避免旧执行者删除新结果。

## 新增文件与职责

- `KnowledgeIndexTaskStore`：任务入库、查询、数据库时间租约、领取、续租、重试和完成事务。
- `KnowledgeIndexClaim`：单次执行权及批次标识。
- `KnowledgeIndexTaskDispatcher`：每实例受限分派及心跳，不扫描对象存储。
- `KnowledgeIndexTaskProperties`：调度开关、重试次数、租约与退避参数。
- `KnowledgeIndexTaskResponse`：面向管理员的状态，不公开执行令牌。
- `KnowledgeIndexSelection`：获准文档与有效索引批次。
- `V20__create_knowledge_index_tasks.sql`：任务表及文档有效批次字段。
- `KnowledgeIndexTaskIntegrationTest`：事务、API 权限、并发领取、过期恢复与发布边界。
- `KnowledgeIndexTaskMigrationTest`：从 V19 升级时旧执行中任务的处置与历史就绪资料兼容。
- `KnowledgeIndexTaskDispatcherTest`：线程池拒绝后的恢复、执行中心跳及每实例限流。

## 修改文件与职责

- `KnowledgeDocumentIndexingService`：原内存异步提交改为持久化入队；增加保存元数据并提交、任务查询。
- `AdminKnowledgeBaseController`：增加 submit 和 index-task 管理接口，修订 202 的语义。
- `KnowledgeDocumentPersistenceService`：文档行锁，串行化任务提交与删除。
- `KnowledgeDocumentServiceImpl`：删除与提交互斥；删除有任务的文档时清理所有 ES 批次，任务级联删除。
- `KnowledgeDocumentIndexWorker`：执行前及各 Embedding 批次间检查租约，按批次写入，使用令牌提交完成或失败。
- `KnowledgeDocument`：有效索引批次字段。
- `KnowledgeChunkStore`、`ElasticsearchKnowledgeChunkStore`：隔离写入、映射升级及两路召回批次过滤。
- `KnowledgeRetrievalService`：将文档有效批次传给检索存储。
- `application.yaml`、`application-test.yml`：任务配置；测试禁用自动调度以确定性驱动流程。
- 既有工作者、检索和 ES 协议测试：适配新协议并检查隔离；README、数据库字典和路线同步。

## API 与数据库

- 新增 `POST /api/admin/knowledge-bases/{knowledgeBaseId}/documents/{documentId}/submit`，请求沿用元数据 DTO，返回 202 和 PROCESSING 文档。
- 新增 `GET .../documents/{documentId}/index-task`，返回最近一次任务；未提交返回 `data: null`，不存在或归属不符返回 404。
- 原 `PUT .../metadata` 只保存；原 `POST .../index` 入队、活动任务幂等，终止后显式重新提交。
- V20 新增 `knowledge_index_tasks`、`knowledge_documents.active_index_build_id`，字段、索引、检查约束及级联外键见数据库字典。
- 升级必须先停止旧版实例：旧工作者不认识批次隔离，不能滚动混跑。V20 将历史 PROCESSING 标为 FAILED / INDEX_TASK_MISSING，管理员检查后重新提交；不自动接管旧内存任务。

## 限制与后续

- 本轮未实现上传新版、安全替代、OSS 外部同步、段落级向量复用、前端入口；后续按 B2/B3 推进。
- 队列至少一次执行，重复模型调用可能发生；不承诺恰好一次。初版每实例单任务，后续已扩展为可配置并发，见下方补充。
- 租约检测进程退出或心跳中断；不代表有每份文档的强制执行总时限。解析器卡住但心跳仍正常时需运维介入，后续可补执行时限。
- 任务表只保留最近一次提交及本轮次数，不是完整任务审计历史。
- 过期或失败批次可能残留 ES，当前依靠检索过滤保证不可见，文档删除会清理；周期垃圾回收后续实现。被挂起的旧工作者在文档删除后仍可能写入孤立批次，但不会被准入检索。
- 在外部文件被绕过 API 修改的情况下不保证快照一致性；当前托管对象按唯一键保存，应通过本系统维护。
- H2 并发测试与 HTTP 协议模拟不能替代真实 MySQL 多进程和 ES 故障演练；实际部署共用数据库及 OSS，不能依赖节点本地文件。
- 原对象存储删除与数据库提交也不构成分布式事务，仍有中断补偿限制。

## 补充：按空闲执行位并发索引

### 行为与业务规则

- 每实例默认同时执行 3 份文档，配置 `app.knowledge.index-tasks.concurrency`，环境变量 `KNOWLEDGE_INDEX_CONCURRENCY`，最小值 1，重启后生效。
- 每 2 秒分别续租已运行任务，并为每个空闲位置分派工作。执行线程就绪后逐个调用原 `claimNext()`，每份文档保持独立事务、令牌、租约和 ES 批次；没有把一批文档合成一个事务或任务。
- 每个执行位从提交线程池到执行结束均保持占用，避免重复分派。完成一个即可在下次调度补入一个，无需等待其他任务。
- 某个任务续租异常会记录日志，继续处理其他执行位；原有执行权检查和数据库租约到期规则不变。

### 文件职责与接口变化

- `KnowledgeIndexTaskProperties` 增加并发配置；`application.yaml` 提供对应环境变量。
- `KnowledgeIndexingConfiguration` 使用相同配置设置核心、最大线程数及有界等待队列容量。
- `KnowledgeIndexTaskDispatcher` 用固定执行位列表取代单一 busy/running 状态；内部 `Slot` 保存各自占用标记与运行任务。
- `KnowledgeIndexTaskDispatcherTest` 保留单执行位回归，增加真实索引线程池的并发行为验证。
- README 和架构文档同步配置与调度说明；无新增业务文件，无 API 或数据库结构变更。

### 验证与限制

- 定向运行调度器、任务集成及迁移测试，共 15 项全部通过。新增 1 项验证：三份文档并发执行、满额时不额外领取、分别续租、完成后领取后续任务。
- 任务集成测试使用 H2；并发调度测试使用真实线程池与模拟工作者，未执行真实 OSS、ES、向量模型的吞吐压测，也未部署或重启运行中的服务。
- 并发数为单实例上限，多实例会叠加；数据库领取仍逐条进行，不是批量 SQL 优化。实际吞吐受文档大小、模型配额和 ES 能力影响。
