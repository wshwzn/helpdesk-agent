# 文档新版与审核交接

## 业务行为与设计

本轮完成 B2：针对已有文档上传候选新版，使用 B1 持久任务索引，管理员审核后原子交接。旧版的原始文件、索引及业务元数据保留；旧版在自身有效期内且未主动撤回时，持续服务至审核确定的交接边界。

上传指定 predecessor 文档，继承 sourceKey、applicabilityScope，提交新 businessVersion 及有效期。来源身份不依赖文件名或 OSS 对象创建时间。文件 SHA-256、解析扩展名和业务元数据都相同才视为无变化：与旧版相同返回 UNCHANGED，与同父候选相同返回 EXISTING，均不重复上传或入队；同版本但不同内容/日期/父关系返回冲突。新的业务版本即使文件相同也需独立构建，未做向量复用。仅文件名变化不构成更新，原候选文件名保留。

新候选要求旧版当前 READY + PUBLISHED、有效且没有已审核接替者，使用旧版乐观锁防止过期页面创建。完全相同的重复请求只读取结果，允许旧版锁版本已经因审核变化；返回文档真实状态，不自动复活失败或撤回记录。可存在多份不同版本的候选，同时审核时只有一个成功。

新候选元数据在上传时固定，普通 metadata / submit 不允许改写，普通 publish 不允许直接发布。上传后自动入队，候选失败不改变旧版。需要修改候选元数据时另建候选；未审核且停止处理的候选可删除，上传中或处理中不能删除。

审核同时校验双方乐观锁、候选 READY、来源范围一致。实际交接时间为 max(审核时刻, 新版声明 validFrom)，精度微秒；旧版 validUntil 必须覆盖到该时刻，新版 validUntil 必须晚于该时刻。一个事务设置旧版 successor/superseded、新版 activated/PUBLISHED。原业务有效期不被改写：实际准入区间为业务有效期与审核边界的交集。未来交接依赖准入 SQL 的半开区间，不需要在零点准时运行定时任务。

撤回尚未启用的新版同时取消旧版退出边界；已启用后撤回不自动恢复旧制度。旧版已有待启用接替者时禁止先撤回旧版，避免制造间隙。已审核链及被候选引用的记录禁止物理删除，保留文件和来源历史；未审核失败候选可清理，任务通过既有外键级联删除。

## 事务、并发和兼容

- 预留候选先锁旧版，去重查询与新记录保存同事务；OSS 上传在事务外。文件上传完成后的 PENDING 与任务入队是另一个原子事务。
- 上传失败只将仍在 UPLOADING 的候选标为失败；迟到补偿不能覆盖已入队状态。原始对象不覆盖旧版，不按文件名复用对象键。
- 审核、取消交接和删除候选使用旧版→候选的锁顺序；任务完成仍使用文档→任务。双方版本号防止并发审核错切。
- 实际检索和回答交付前复查都复用准入服务，因而同时受交接边界约束。证据元数据从 MySQL 取有效区间；ES 中的原元数据快照无需就地修改。生成期间若审核改变了证据资格或有效期，既有最终复查会拒绝交付该次旧证据结果。
- V21 四字段默认 NULL，旧文档不自动关联、不自动失效。普通上传/独立发布仍兼容；保证范围是明确关联的版本对，不是全库同源冲突裁决。
- 旧程序不理解 activated/superseded，部署需升级所有问答实例后再启用替换，不将混跑视为安全部署方式。

## 新增文件与职责

- `UploadKnowledgeRevisionRequest`：上传时的旧版锁版本、新业务版本和有效期，统一微秒精度。
- `ApproveKnowledgeRevisionRequest`：审核双方的乐观锁版本。
- `KnowledgeRevisionUploadResponse`、`KnowledgeRevisionApprovalResponse`：上传结果分类、审核后双方状态及交接时刻。
- `KnowledgeUploadFile`、`KnowledgeUploadSupport`：共用文件校验、名称清理、哈希与独立对象键。
- `KnowledgeDocumentRevisionService`：编排文件预处理、预留、对象写入、入队与失败补偿。
- `KnowledgeRevisionPersistenceService`、`KnowledgeRevisionPreparation`：事务内去重、预留候选、完成上传和有条件补偿。
- `KnowledgeRevisionRules`：上传与审核共用的旧版可替代规则。
- `V21__add_knowledge_document_revisions.sql`：版本关系和审核边界、索引及外键。
- `KnowledgeDocumentRevisionIntegrationTest`：真实解析/分块、任务和事务配合的版本流程、并发及接口验证；模型、ES、存储使用替身。
- `KnowledgeDocumentRevisionMigrationTest`：V20 升级兼容及悬空关系防护。

## 修改文件与职责

- `KnowledgeDocument`、`KnowledgeDocumentResponse`：暴露前驱、后继与审核时间边界，不公开 OSS 地址。
- `KnowledgeDocumentServiceImpl`：复用文件校验；限制上传中删除，删除候选统一锁顺序并保护版本历史。
- `KnowledgeDocumentPersistenceService`：保护被引用/已审核记录的删除。
- `KnowledgeDocumentPublicationService`：审核交接、取消未来安排、防止普通发布与元数据修改绕过新版流程。
- `KnowledgeDocumentEligibilityService`：增加 activated/superseded 半开区间过滤。
- `KnowledgeDocumentMetadata`：证据使用有效期与交接区间的交集。
- `AdminKnowledgeBaseController`：上传候选和审核接口。
- `AdminKnowledgeBaseControllerIntegrationTest`：适配新增响应字段。
- README、数据库字典、后续路线：接口、关系和阶段进度同步。

## API 与数据库变化

- `POST /api/admin/knowledge-bases/{baseId}/documents/{旧版ID}/revisions`：multipart 的 file + application/json metadata，新增返回 202，UNCHANGED / EXISTING 返回 200。
- `POST /api/admin/knowledge-bases/{baseId}/documents/{候选ID}/approve-replacement`：请求 version + predecessorVersion，返回 predecessor、successor、effectiveAt。
- 原 withdraw 对待生效的新版增加取消交接语义；旧索引重试接口仍可用于失败候选。
- V21 新增 predecessor_document_id、successor_document_id、activated_at、superseded_at；前驱普通索引、后继唯一约束及两个自引用外键均见数据库字典。旧迁移未修改。
- 关系配对、同库同源同范围及无循环由应用事务保证；未加入引用自增 id 的 CHECK。非受控 SQL 直接修改关系不在保证范围内。

## 已知限制与后续

- 未实现 OSS 外部来源扫描、在线正文编辑、向量复用、全库冲突裁决和前端操作入口；下一步 B3 接入一种明确管理的外部来源。
- 索引失败可走既有任务重试；上传失败保留候选便于诊断，完全相同请求返回该记录而不自动重传。确认上传失败的候选可删除后重传。
- 进程恰在候选预留与对象上传/入队之间崩溃时，可能遗留 UPLOADING 记录或孤立对象；没有新增上传租约和自动清理器，需排查后人工恢复。持久索引任务的重启恢复不等同于整个文件上传事务可恢复。
- 已审核版本保留策略尚无归档清理入口；候选元数据需调整时另建候选。尚未生效新版可通过撤回取消，已生效不自动回滚旧制度。
- 更新保证限于明确的版本链；保留的普通上传/独立发布入口仍可能形成未关联的重叠资料，可信问答按现有冲突处理规则运行。
- 业务时间使用 Asia/Shanghai 的 knowledgeClock，多实例需要正常时间同步；本轮不新增分布式时钟协议。
- 测试不等于真实 OSS、ES、MySQL 多实例故障演练；未重启本地后端，未修改现有练习库。
