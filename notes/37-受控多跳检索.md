# 受控多跳检索（C2）

## 行为与业务规则

受控多跳初版已实现并完成首次真实对照，C 阶段仍有三个问答缺口待收敛。首轮使用原问题；最多两次规划、各两次补查，总上限三轮、五次搜索。知识库和范围全程绑定。累计证据按文档主键与块序号去重，原文变化即失败，50 个片段 / 50,000 字符超限明确失败，不静默裁掉冲突。90 秒为补查调度软预算，不是单次 HTTP 或整轮问答的硬超时。

停止原因包括充分、真实用户条件缺失、搜索耗尽、重复查询、无新增证据、轮数或时间耗尽；技术故障不当成正确拒答。首轮无命中保持 NO_MATCH；本轮不做空召回改写。规划只辅助检索，不进入最终证据，最终继续引用目录解析、语义复核、资格复查。

## 新增和修改文件

- `KnowledgeRetrievalPlan`：严格规划动作、缺口和查询协议。
- `KnowledgeEvidenceCollector`：有界检索、去重、累计和停止；`KnowledgeMultihopProperties`：对照开关和调度时间。
- `KnowledgeRetrievalRun`：逐次搜索、规划及停止原因。
- `KnowledgeAnswerModelClient`：独立规划提示和用量保留；最终草案与复核提示保持原样。
- `TrustedKnowledgeAnswerService`：接入累计证据和规划用量，保留全部最终核验。
- `KnowledgeAnswerTrace/RunSnapshot`：快照版本 3，增加 PLANNING 阶段和 retrievalRun；旧 retrieval 字段仍指首轮，旧快照可读。

- `application.yaml`：默认开启多跳及 90 秒调度预算；可关闭用于单轮对照。
- `KnowledgeEvidenceCollectorTest`：次数、稳定证据身份、预算、重复、无新增、取消、错库、内容变化、失败及未知用量。
- 原服务/模型/诊断/澄清测试：覆盖规划协议、最终复核与撤回、多轮诊断持久化及旧快照读取。
- `evaluate_knowledge_multihop.py`：兼容首轮与累计召回口径，复用冻结库并验证配置，支持跳过人工探针；`evaluate_trusted_knowledge.py` 纳入 PLANNING 已知用量。
- Python 测试覆盖多轮召回并集、缺失/截断诊断、规划成本、实际响应字段名。
- README、路线、评测说明、数据库字典及题集 README：更新实现状态和诊断契约。冻结题目和 18 份正文不变。
- `docs/evaluation/runs/2026-10-21-受控多跳首次对照.md` 及数据 JSON：完整逐题复查、失败和成本；预检记录单独归档。

## API / 数据库

客户问答接口和答案契约不变；管理员诊断 JSON 新增 retrievalRun。无 DDL 变更，无新增数据库迁移；数据库字典同步 JSON 字段语义。新增安全错误码 KNOWLEDGE_PLANNING_CALL_FAILED。未配置知识库时不再记录虚构的 RETRIEVAL 阶段。

## 限制与后续

有限补查不保证发现全库全部冲突；规划判断仍可能错误。模型与检索调用进行中不靠软预算硬中断；取消沿已有会话取消机制。固定题集后续对照，保留全部失败。

预算约束的是应用逻辑调用，SDK 原有 HTTP 重试不计入逻辑次数，未返回重试用量也不计入已知 Token，因此不能声称完整物理调用预算或账单。最终草案与复核仍可能消耗额外时间。首轮无命中不改写查询；未新增任意文档读取接口，当前补查只使用获准的检索片段。

下一步先解决 N02 的过早停止、N01 资料缺失与用户条件混淆、N04 部分可答复核可诊断性，再验收 C 并进入 D。该结果仅是开发样本首次观察，非泛化准确率。
