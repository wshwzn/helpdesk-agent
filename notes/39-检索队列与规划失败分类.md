# 检索队列与规划失败分类

## 实现行为与业务规则

本轮只修正阶段 38 候选中的可验证程序问题，不增加复核策略。候选开关仍默认 false，BASELINE 复核和阶段 37 默认规划保持不变。

候选使用一个请求内查询队列：每次规划先按原顺序加入 queries，再加入 ruleChecks.query；按 NFKC、空白和大小写归一化去重，新任务追加到队尾。已执行项先过滤，再取本轮最多两个实际搜索名额。未执行任务跨轮保留，核查不能再插队挤掉同次规划中的并列问题查询。

核查完成情况单独记账，只能由成功返回的实际搜索解除。下一规划省略旧核查不会抹掉责任；SUFFICIENT 也不能跳过未完成核查。当前批次无新增证据、但还有排队任务时，允许在原预算内继续；队列已空才以 NO_NEW_EVIDENCE 停止。最多三轮、五次搜索、两次规划，以及时间/证据预算均不增加。最新规划非 SEARCH 且无待核查项时仍可停止，普通查询建议不变成永久执行义务。

规划协议失败细分为固定错误码，校验顺序为载荷解析、字段、动作组合、查询与规则词关系、原文锚点。只记录分类与已有 Token 用量，不存模型原始坏输出、厂商异常或动态字段内容。原有长度、字段必填、动作和逐字锚点约束没有放宽。

## 新增与修改文件

- 新增本说明，无新生产类。
- KnowledgeEvidenceCollector：统一候选查询队列，跨轮保留、执行前去重、预算和无新增停止衔接。
- KnowledgeRetrievalPlan：拆分校验分支及固定分类，原默认协议校验保持不变。
- KnowledgeAnswerFailure：增加五类规划错误及保留分类的用量包装方法。
- KnowledgeAnswerModelClient：不再把具体规划校验错误重新包成通用协议错误；只同步一处关于调度顺序的提示说明，其余规划要求和复核策略不调优。
- KnowledgeEvidenceCollectorTest：验证并列问题先执行、核查跨轮保留、重复项不占名额，并检查错误分类。
- KnowledgeAnswerModelClientTest：五种独立固定坏输入穿过真实解析/校验，检查分类、用量及不携带原始内容。
- KnowledgeAnswerRunIntegrationTest：验证规划分类、阶段和用量经消息/诊断落库及管理员接口仍完整，且失败后不生成草案。
- README、路线、评测说明、数据库字典：同步候选状态和错误码，保留阶段 38 历史失败记录。

## API 与数据库

无新接口、无 DDL、无快照字段变化，schemaVersion 仍为 4。HTTP 仍返回原 CHAT_GENERATION_FAILED；消息历史和管理员诊断可看到以下固定错误码。默认旧协议继续使用原错误分类。

| 错误码 | 意义 |
| --- | --- |
| KNOWLEDGE_PLAN_PAYLOAD_INVALID | 无法按规划载荷解析，如畸形 JSON、未知字段或空结果 |
| KNOWLEDGE_PLAN_FIELDS_INVALID | 必填字段缺失、长度/数量/查询控制字符不合法 |
| KNOWLEDGE_PLAN_ACTION_INVALID | 动作与列表组合不合法，例如充分判断没有核查项 |
| KNOWLEDGE_PLAN_RULE_QUERY_INVALID | 核查查询不包含所声明规则词 |
| KNOWLEDGE_PLAN_RULE_ANCHOR_INVALID | 所声明证据编号与逐字规则词无法在实际原文匹配 |

## 验证

针对性测试的首次运行有六项断言仍期待旧通用错误码；更新为新分类契约后，完整 `mvn -q test` 通过：297 项测试，0 失败、0 错误、0 跳过。`mvn -q -DskipTests package` 打包通过。新增调度测试使用固定依赖桩，五类坏输入为独立构造，不是重跑真实模型选出的样本。

本轮不调用真实模型、不切换默认库、不修改评测原文和题集。阶段 38 的三次规划失败没有原始坏输出，不能追溯补造原因；本次分类用于定位之后的新运行。既有 7/12 候选成绩保持原样，不用单元测试替代端到端效果声明。

## 限制与后续

统一队列解决了已观察到的核查抢占，但不能证明规划所选规则与业务相关；旧任务也可能占用后续预算。若最终仍有规则未查，原回答状态约束继续阻止 ANSWERABLE，不自动扩大预算。原文锚点成立不代表召回完整，更不代表推理正确。

下一步先做一次有明确输入和错误分类的独立规划协议回放，评估候选是否值得继续；达到准入条件后再安排真实端到端对照。暂不启用候选、调整复核策略或推进 D 入口统一。

本轮未重启本地后端，运行中的阶段 38 默认关闭制品继续提供服务。代码与打包制品已更新；后续真实协议回放必须记录新制品标识，不混用旧进程。
