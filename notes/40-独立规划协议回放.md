# 独立规划协议回放

## 实现行为与规则

新增显式运行的规划回放工具，使用独立设备制度场景验证阶段 39 的候选协议。只读取默认模型配置并调用规划器，不执行知识检索、生成草案或复核，也不修改业务数据。普通 Maven 测试只用模型桩，不触发计费调用。

事前固定 8 题、各两遍；全部协议和场景动作检查通过并经逐条阅读后，才考虑完整问答验证。标签与准入规则不发送给模型；所有调用保留有效规划或固定失败码、用量和耗时，不保存无效原始输出。新运行目录禁止覆盖，中断、不完整或重复身份不能算通过。

## 新增与修改文件

- `docs/evaluation/knowledge-planning-cases.json`：8 个独立虚构场景、暂定动作标签和准入标准。
- `KnowledgePlanningEvaluationCli`：复用已有只读模型配置启动环境，执行规划、保留固定错误分类和成本。
- `scripts/evaluate_knowledge_planning.py`：构建、启动 CLI、记录源码/题集摘要、汇总完整性和自动门槛。
- `KnowledgePlanningReplayTest`：验证输入身份、标签隔离和失败保留。
- `scripts/test_evaluate_knowledge_planning.py`：验证完整性、重复身份、失败及未知成本的计分边界。
- 新增真实回放报告及全量 JSON：保存全部 16 次规划和运行条件。
- README、路线及评测说明：同步真实结果与候选未启用状态。

生产代码未改，无新 HTTP API、DDL 或快照字段变化，无数据库文档结构变更。

## 验证与实际结果

新增 3 项 Java 测试通过，39 项 Python 测试通过；显式 CLI 构建与执行成功。未重复跑全量 Java 测试，未重启后端。

真实 16 次调用：协议 16/16 合法、0 技术失败，场景检查 15/16；Token 16,106，平均 2.089 秒。唯一未通过是 P01 第一遍选择额外核查，而事前只允许 SUFFICIENT。它不是协议或答案错误，标签偏窄且 SUFFICIENT 自身也可能补查；原标签及失败计分保留，不能借此宣称产品退化。

逐条阅读还发现已知数值进入其他子问题的查询，以及用户条件被重复归入 gaps 等语义偏差。规划合法不代表最优，回放不包含检索及最终问答，不能宣称阶段 38 的旧问题已经修好。完整证据见 [回放报告](../docs/evaluation/runs/2026-10-21-独立规划协议回放.md)。

## 限制与后续

自动门槛未满足，候选继续关闭，不运行完整问答评测，不事后调门槛或重跑选优。默认仍为阶段 37 规划和 BASELINE 复核。本轮没有发现新的协议技术故障，但也不足以证明候选提升端到端质量。

不再自动开启另一轮提示调优或添加规则。后续先收敛候选方案的必要性，重点评估重复查询表达和强制核查带来的复杂度，决定保留哪些约束；在明确简化方案前不继续消耗模型调用追求小样本全过。
