# 多范围联合检索与澄清

## 实现行为和业务规则

一次问题最多选择三个范围，先联合检索所选范围及 ALL 通用资料，只生成一次查询向量并调用一次混合检索。初检没有召回专属资料的范围各允许一次定向补查；后续按整题事实缺口继续原受控规划。所有地区共享三轮、五次逻辑搜索、最多两次规划、50 块/50000 字符和90秒软调度预算，不为每个地区单独生成或复核回答。关闭多跳仍只联合初检一次。

范围出现某个片段只是粗粒度覆盖，不代表问题已答全。最终草案与复核逐地区检查问题；资料不足保留有据部分，不用一地规则补另一地，不把不同地区金额差异当成制度冲突。通用规则是否覆盖某地区仍须由原文支撑。引用解析、发布/有效期准入、交付前资格复查、取消约束保持。

请求支持 applicabilityScopes，旧 applicabilityScope 继续接受。禁止空列表、重复、超过三项、ALL混选以及新旧字段冲突。多范围时标量字段为 null，列表为完整范围。未提供范围时，对主题配置中的地区名称作明确文本匹配；单地区直接检索，多地区保留比较意图。否定表达、比较却只识别到一个地区、超过三个已知地区时保留澄清，不静默截断。多主题提供范围并集。续答可以多选，仍校验原对话最后一条澄清、选项、原知识库和配置修订。

## 新增文件和职责

- KnowledgeScopes：统一新旧字段、范围数量与组合校验。
- KnowledgeScopesTypeHandler：将消息范围列表保存为 JSON，兼容历史空值。
- V23__add_message_applicability_scopes.sql：增加消息多范围列，不改历史迁移。
- KnowledgeScopesTest：验证新旧请求与无效范围集合。
- KnowledgeScopeConflictTest：不同地区金额差异不能单独构成冲突，同范围和ALL重叠仍交由语义核验。
- 多范围真实验证脚本与资料：只用隔离测试库，保留结果并恢复原默认库。

## 修改文件和职责

- SendMessageRequest、KnowledgeSearchRequest、KnowledgeAnswerInput：接入范围列表，保留旧构造入口。
- ChatMessage、ChatMessageResponse、ConversationPersistenceService、PreparedChatExchange：保存请求与有效范围、多选续答、历史回读；推断多范围时正确清空旧标量。
- ConversationServiceImpl：多选请求使用完整输入入口，修复非续答只传旧标量造成的范围丢失，同步和流式共享此修复。
- KnowledgeDocumentEligibilityService、KnowledgeRetrievalService：一次筛选准入文档并联合召回，向量化一次；网络调用后重新检查资格。
- KnowledgeEvidenceCollector：新增有限多范围编排；缺地区补查和事实补查共享预算，按查询与范围组合去重。
- KnowledgeApplicabilityService：配置名称识别、多主题范围并集。
- TrustedKnowledgeAnswerService、KnowledgeAnswerModelClient、KnowledgeAnswerGuard：整题一次生成与复核，按地区检查覆盖、拒绝仅因不同地区形成的伪冲突。
- KnowledgeAnswerReport、KnowledgeAnswerTrace、KnowledgeAnswerRunSnapshot、KnowledgeRetrievalRun：保存有效范围及每次搜索过滤范围。
- GlobalExceptionHandler：反序列化失败返回固定400错误，不输出原始请求内容。
- 检索、文档资格、采集器、澄清集成和请求测试：增加联合查询、共享预算、范围过滤、续答和存储兼容覆盖。

## API 和数据库变化

- 消息与管理员 search 请求新增 applicabilityScopes 数组；单范围旧客户端无需修改。
- 消息响应和报告增加 applicabilityScopes；报告新结果版本3、诊断版本6，逐次 search 增加 scopes。旧 JSON 可读，旧诊断缺少的范围不补造。
- V23：chat_messages.applicability_scopes LONGTEXT NULL，默认NULL，保存最多三项范围代码的JSON。历史行从 applicability_scope 恢复；无新增索引、外键或唯一约束。
- 旧 AGENT 仍不接受范围选择；这轮不宣称已完成 D 的入口统一。

## 验证

`mvn -q package`：314项Java测试通过，0失败/错误/跳过，打包成功；评测脚本4项单元测试通过。V23已在本地MySQL执行，H2迁移测试通过。同步和流式集成测试使用不含地区名的正文，确保显式列表完整传入检索且不重复路由。

真实调用使用当前默认“dp官方”（配置9，deepseek-flash），不回退旧文本模型。首次六题出现会话入口丢失列表，导致通用题持久化失败；正文中的地区名称掩盖了其他显式请求的缺陷。保留首次结果，修复后同组六题只复验一次：五题通过，一题因KNOWLEDGE_REVIEW_REJECTED未交付。广州缺资料时草案已正确保留上海依据并标记不足，但复核拒绝，疑似误拒，具体原因未知，不能宣称完整验收。

修复后资料齐全的比较题只用一次联合搜索，缺资料题四次；每题草案/复核各一次。总29,037已知Token包含失败及澄清初问，Embedding未计入。两次均恢复默认库18，模型配置未改变。由于模型已更换，不与阶段41比较准确率。详见[完整报告与两次原始结果](../docs/evaluation/runs/2026-10-21-多范围联合检索验证.md)。

## 限制和后续

名称识别依赖管理员配置的完整名称，不是通用地名识别；别名、复杂否定、隐含对象等仍需明确范围参数或澄清。粗覆盖不能发现全部语义缺口，通用资料可能引起额外的有限地区补查；不保证全库冲突检出。初检结果总条数不随地区数倍增，有限预算下可以返回部分证据不足。数据范围不是访问权限；多租户或部门ACL不在本轮范围。

前端不在当前仓库，多选请求契约已提供，自然语言明确名称可直接使用；不声称完成外部前端多选控件。后续仍是统一可信问答入口，保持阶段41候选关闭，不重开其提示调优。
