# 问答复核与一次修订

## 实现行为与业务规则

针对“项目开发记录”中相同证据下有时通过、有时复核否决的现场，增加 GROUNDED 复核策略和最多一次修订。保留充分解释，不改变管理端检索数量、相似度、默认知识库或模型配置。问题相关的事实、条件和相反证据仍要核验；区分历史阶段记录与当前能力，不凭文件名或上传时间认定替代关系。

GROUNDED 复核必须返回合法原因及可定位缺陷。批准时 reason=NONE、issues=[]；否决须有 1–5 个问题，路径与证据必须存在。首次具体否决后，原问题、同一引用目录、原选择及复核缺陷交给模型修订；反馈不被当作事实，模型仍须核对原文。修订可保留有据部分并选择不足/冲突状态，但不得编造结论、机械删除必要限制或退化为空白拒答。

修订重新执行引用解析、结构、范围及检索上下文约束、语义复核，交付前仍复查文档资格和澄清配置。第二次否决即失败；协议错误、外部调用错误不重试求批准。没有具体缺陷的旧布尔协议仍保持原否决行为。取消终态阻止后续修订与迟到写入。

新诊断 schemaVersion=7，answerAttempts 保留两轮选择、草案与判断。新增 REVISION 阶段，每次模型用量独立保存并累计，不能用最终一轮掩盖首次失败成本。首次复核阶段 SUCCEEDED 仅表示合法调用完成，批准与否看 review.approved。客户只获取最终通过核验的回答。

## 新增文件与职责

- `src/test/java/com/anying/helpdesk/knowledge/answer/evaluation/KnowledgeAnswerRecoveryEvaluationCli.java`：显式真实模型回放，冻结检索和资格依赖，复用生产问答编排；不由普通测试调用，不作为线上端到端验证。
- `scripts/evaluate_knowledge_recovery.py`：构建、固定输入摘要、不可覆盖的输出、逐条结果保存与交付/校验统计；交付不自动记为语义正确。
- `scripts/verify_real_knowledge_answers.py`：对已有“项目开发记录”执行四个在线问题，逐题独立会话，只请求一次，检查前后配置不变。
- `docs/evaluation/knowledge-recovery-cases.json`：两个真实问题完整现场、固定重复次数、真实资料错误断言及既有负例/部分可答正例；准入标准预先写入。
- `docs/evaluation/runs/2026-10-28-开发记录澄清问答失败诊断.md`：原始问题只读排查依据。

## 修改文件与职责

- `KnowledgeAnswerModelClient`：新增按问题及阶段语境核验的策略、严格缺陷协议、一次修订模型请求；原策略保留用于对照。
- `TrustedKnowledgeAnswerService`：复用同一校验路径修订一次，合计四次潜在模型调用成本。
- `KnowledgeAnswerRunSnapshot`、`KnowledgeAnswerTrace`：保存多次尝试，兼容历史 JSON，取消后不追加尝试。
- `KnowledgeAnswerFailure`：新增修订外部调用故障码。
- 三个问答测试类：覆盖一次修订、再次否决、伪造引用、取消、调用故障、严格协议、数据库诊断往返和客户隔离。
- `evaluate_trusted_knowledge.py`、`evaluate_knowledge_scopes.py`：将 REVISION 纳入模型调用与用量统计；相关计费统计测试更新。
- `docs/database-schema.md`：同步 JSON 快照语义，无表结构变化。
- `application.yaml`：默认采用 GROUNDED；可通过 KNOWLEDGE_REVIEW_STRATEGY 或同名 Spring 属性显式回到 BASELINE。README、架构、交付清单同步当前链路，历史失败报告不改写。

## API 与数据库

无新 HTTP 接口，无 DDL，无 Flyway 迁移。管理员诊断 JSON 增加 answerAttempts 和 REVISION 阶段；成功客户消息格式不变。新增错误码 KNOWLEDGE_REVISION_CALL_FAILED。

## 测试与人工验证

- 全量 Java 336 项通过，Python 53 项通过。修改默认配置后全量Java测试再次通过；打包一度因隔离进程占用JAR失败，停止本轮隔离进程后打包成功，随后复制专用JAR验证，避免覆盖运行中的构件。
- 冻结真实证据回放：两题各两次，BASELINE 1/4 完成、3/4 复核否决；GROUNDED 4/4 完成，其中一次经针对性修订通过，其余首次复核通过。五个错误草案和一个部分可答正例，两策略均 6/6 正确判断，无技术异常。
- 阅读四份候选答案，保留了澄清流程、条件、范围兼容、引用与问答链路的详细解释。真实修订纠正了缺范围必追问、单范围续答字段和遗漏诊断阶段的描述，未通过空白拒答规避问题。复核理由仍是模型意见，不当作人工金标准。
- 回放共 30 次实际模型调用，已知文本 Token 854499；其中 BASELINE 395890，GROUNDED 458609，全部有用量。生成与复核回放不含检索、规划、Embedding。一次修订的复杂问题耗时 266.2 秒，不能宣称新机制一定更快。
- 新服务可读取旧 schemaVersion=6 的原失败记录，answerAttempts 保持 null，不补造历史原因。
- 用户在排查过程中把当前检索结果上限改为10；本轮工具未写该配置。回放仍保持历史50条，在线验证按当前10条执行，分开报告。
- 在线四题均完成、42个引用检查通过、诊断4/4，资料、模型及检索配置前后不变；K04经一次修订补齐独立发布与关联审核交接的前提。在线14次模型调用、176226文本Token，不含Embedding。
- **人工核对K03发现语义缺陷**：引用机制主体说明有据，但开头把早期search_knowledge_base工具流程写成当前流程。保留该问题，自动4/4不能冒充语义全对。历史语境识别仍不稳定，是后续独立问题。
- 在线脚本首题完成后因公共报告所需字段缺失停止；补齐字段并增加真实格式化/续跑单测，仅继续后三题，没有重复首题。首题和后续的运行构件摘要分别保存，Java源码相同。
- 完整结果见[验证报告](../docs/evaluation/runs/2026-10-28-真实资料问答复核改进.md)、回放和在线原始JSON。本轮仅在8081隔离服务验证；用户IDEA启动的8080旧进程需要重启才能加载新默认行为。
- 首次构建评测入口时发现 Long 字段传入 int，已修正；该次未发生模型调用。所有真实模型结果保留，不重跑选优。

## 已知限制与后续

语义复核仍依赖同一模型的独立调用，具体理由也可能误判；一次修订不能保证全部问题成功。修订增加失败路径的时延与 Token 成本，复杂路径可能接近现有SSE等待时限。冻结证据回放不覆盖真实检索变化、交付期间资料变化或完整前端 SSE；在线只验证了当前库四题HTTP链路，不声称完整历史题集或SSE已重测。不会把无错误详情的旧失败记录改写成已修复，也不会隐去K03的历史架构混用。
