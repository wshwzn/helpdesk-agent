# 自然语言追问与上下文

## 实现行为

普通提问有历史时增加一次上下文补全调用，再复用原来的检索、生成、引用解析与语义核验。首轮不增加调用；明确携带 clarificationMessageId 的范围卡片续答仍使用原有服务端恢复逻辑，不重复改写。

历史来自当前已鉴权会话、本轮用户消息之前的最近六条已完成 KNOWLEDGE 用户/助手消息，按时间顺序发送，每条最多 2000 字；失败回答、工具消息与旧 AGENT 内容不加入。窗口通常对应最近三轮，失败问答可能不成对，不承诺长期记忆。

模型将“那北京呢？”补为独立问题；换话题保持新问题语义，当前明确条件优先于历史。历史回答只用于理解主题和指代，不传入生成、核验作为证据。补全依然可能误解语义，重新检索不能保证补全理解完全正确。

指代不清时返回一个简短澄清问题，状态 NEEDS_CLARIFICATION，reason 为 CONTEXT_REQUIRED，跳过检索；用户用普通文本补充说明后，下一轮连同澄清文字一起理解，不要求新的续答参数。范围卡片仍使用 APPLICABILITY_REQUIRED，不能混用。

## 文件变化与职责

- 新增 `KnowledgeConversationContext`：补全问题/澄清结果及轻量历史消息结构，无额外服务或记忆框架。
- `ConversationPersistenceService`：限定当前会话和消息边界读取最近历史。
- `KnowledgeAnswerModelClient`：新增上下文提示词与结构解析，复用现有模型调用和 Token 读取；两种结果互斥，不增加自动重试。
- `ConversationServiceImpl`：同步与 SSE 共用补全入口；恢复为独立问题后调用原可信服务，累计上下文用量，未知用量仍为 null。
- `KnowledgeAnswerTrace`、`KnowledgeAnswerRunSnapshot`：新增 CONTEXT 阶段和 conversationContext 诊断字段；原始用户问题不变，快照版本升为 8，旧快照该字段为 null。
- `ChatStreamEvent`：阶段提示“正在结合上下文理解问题”，现有前端可直接显示。
- `KnowledgeAnswerReport`：新增 CONTEXT_REQUIRED；澄清不附带伪造引文。
- `PreparedChatExchange`、`README.md`、`docs/database-schema.md`：同步上下文与诊断契约说明。
- 两个评测统计脚本将 CONTEXT 纳入模型调用次数与用量统计。
- 现有会话集成测试增加追问、换话题、澄清后补充三种关键流程；模型协议测试验证结果解析。旧诊断和澄清测试更新快照版本与默认模型桩。

## API 与数据库

无新增接口、请求参数或表字段，无 Flyway 迁移。消息仍保存用户原话；管理员运行快照通过 conversationContext.question 查看实际补全的问题，或通过 conversationContext.clarification 查看不明确时的追问。SSE 增加 CONTEXT 阶段，报告 reason 新增 CONTEXT_REQUIRED，回答状态继续使用原有 NEEDS_CLARIFICATION。

## 验证

全量执行 351 项 Java 测试，最初 349 项通过、两条旧会话用例因缺少新增上下文调用桩失败；补齐后重跑会话与模型协议相关 77 项全部通过。其余已通过测试未重复运行。两组评测统计脚本共 17 项测试通过，`git diff --check` 通过。

本轮只新增 4 个执行用例：追问、换话题、指代不清后继续补充、上下文模型协议；复用原有集成测试设施。验证补全问题进入可信服务、原输入保留、历史范围可读、用量累计、诊断保存和 SSE 澄清流程。使用确定性模型桩验证编排和数据边界，未调用真实付费模型，不把预设模型输出的通过率宣称为真实模型理解准确率。

## 限制与后续

有历史的普通提问会额外调用一次模型，增加延迟和用量。只支持短期文字上下文，不做长期摘要、历史向量检索、工具调用、知识库跨会话记忆或回退重试。历史中已失效的事实必须在本轮重新检索核验。未改前端使用说明中的旧措辞；前端已有阶段和普通澄清显示可复用。服务器不会自动更新，需另行部署。
