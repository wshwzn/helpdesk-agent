# 公开制度检索对照评测

## 实现行为与业务规则

- 新增管理员完整候选查询，复用发布状态、有效期、范围、模型及索引批次准入和原有 RRF，只扩大返回上限为候选窗口两倍；普通检索和问答结果上限不变。
- 固定 23 份深圳大学公开制度资料，按正文和段落摘要绑定来源。原 HTML 和正文留在忽略目录，仓库保存来源、问题、段落标签与无正文的排名证据。
- 100 题先划分 30 开发集、70 测试集，另外 10 题无答案问题留作后续拒答评测。标签明确为 AI 辅助、待独立人工复核，不能宣称人工标注或真实用户数据。
- 同一次查询保留完整双路候选，从原始名次比较 BM25、向量、RRF，避免融合截断造成基线偏差。分别统计参考文档与完整证据段落的命中、召回、MRR，额外统计找齐全部证据的比例。
- 同文档或段落重复命中不重复计分；多证据问题分组统计；每题等权宏平均；技术失败计零并保留分母；开发与测试标签不能共享同一段落。
- 在独立知识库导入、索引和发布资料；不改变用户默认知识库。三种方案使用同一实验性资料准入集合，不评测现实制度有效期。

## 新增文件及职责

- `scripts/prepare_public_retrieval_corpus.py`：下载、缓存、提取正文、冻结来源与段落摘要；后续下载遇到内容漂移即停止。
- `scripts/evaluate_public_retrieval.py`：题集校验、专用库初始化、真实检索执行、指标计算、运行快照和环境一致性检查。
- `scripts/summarize_public_retrieval.py`：导出不含制度正文的逐题排名证据与对照报告。
- `scripts/requirements-public-retrieval.txt`：固定网页下载和 HTML 解析依赖。
- `scripts/test_evaluate_public_retrieval.py`：覆盖文档与证据命中区别、重复证据及多文档、候选截断、失败分母四项关键口径。
- `docs/evaluation/public-campus/`：来源清单、固定标签、阅读用问题表、复现说明和初测归档。

## 修改文件

- `KnowledgeRetrievalService`：增加 `searchCandidates`，以临时参数快照请求完整并集，不修改知识库持久化参数。
- `AdminKnowledgeBaseController`：提供管理员候选接口。
- `KnowledgeRetrievalServiceTest`：新增完整并集与普通结果上限不受影响的回归用例。
- README、评测入口与早期检索评测说明：链接本轮实验、数据与指标边界。

## API 与数据库

- 新增 `POST /api/admin/knowledge-bases/{id}/search-candidates`，请求复用 `KnowledgeSearchRequest`，响应复用 `KnowledgeSearchResponse`。
- 沿用已有 ADMIN 路径权限；结果最多为两倍单路候选窗口，上限 400 个片段，仅用于诊断评测，不直接送入问答生成。
- 无数据库结构变更。本地新建库 27“公开制度检索评测-SZU-v1”，共 23 份已发布文档、91 个 chunk；原始网页、令牌、模型凭据不提交。

## 测试与真实验证

- 5 项 `KnowledgeRetrievalServiceTest` 全部通过，其中新增 1 项。4 项 Python 指标测试全部通过；题集引用、摘要及开发测试段落分离校验通过。
- 真实 HTTP 校验候选接口未登录返回 401；评测前后用户默认知识库仍为原库。题集保存在 Git 文件中，没有混入旧管理端只支持文档标签的评测用例表。
- 构建首次在重打包时因 Windows 上运行中的 JAR 被占用而失败；停止本轮启动的进程后重新打包成功，再从本地副本启动进行评测。
- 使用真实本地 MySQL、ES、OSS、默认 `qwen3.7-text-embedding` 1024 维模型完成 23 份资料索引与 100 个问题检索；没有调用聊天模型生成答案。
- 参数固定为候选窗口 25、KNN 候选 50、相似度下限 0.0、RRF 常数 60、chunk 1000/重叠 150；先开发后测试，未根据测试结果调参或改标签。
- 开发 30 题三方案证据 Recall@5 均 100%；测试 70 题零技术失败，证据 Recall@5 为 BM25 95.00%、向量 95.00%、RRF 99.29%。RRF 证据 MRR@5 为 0.8440，低于 BM25 的 0.8636，完整呈现取舍。
- 逐题证据及所有失败归档在 `docs/evaluation/public-campus/runs/2026-11-24-initial.*`；共享请求 P95 为 299 ms，只表示单机串行一轮完整候选查询的耗时。
- 最终代码和脚本通过 `git diff --check`；没有修改前端或部署服务器。当前本地后端从 `data/public-campus/backend.jar` 运行，使用现有本地配置。

## 限制与后续

- 这是 AI 辅助标注的小型自建基准，不是人工金标准；题目从资料构造，主题相关、部分复合题复用单题证据，不能把高分外推到真实线上。应由用户核对 `data/public-campus/人工复核清单.md` 后记录修改并重跑。
- 按完整段落精确包含判断，未穷举所有等价证据；段落截断会影响评分，不等于语义回答正确率。无答案题未执行，故没有拒答率数据。
- `q100` 的分流证据为向量第 2、BM25 未入围、RRF 第 17。保留这个融合失效案例；后续若要调权重或加 reranker，先新增开发问题，不在当前测试题上反复调参再称盲测。
- 源站变化后摘要不匹配会停止；原网页快照和正文保存在本地 `data/`，应随实验备份。全文未加入 Git。
- 未扩建完整评测平台、前端配置界面、模型评分器或数据库表，优先保持可读的小脚本和最小业务接口。
