# 问答交付与引用质量评测

## 实现行为与业务规则

- 在现有公开制度知识库上冻结 70 条测试问题和 10 条资料不足问题的真实 RRF 前十片段。
- 同一初稿作为两组共同输入：基线保留引用结构校验，完整组增加生产语义复核及最多一次修订。检索和资格检查使用冻结替身，不改线上服务或默认知识库。
- 原文参考只传给辅助评分器；逐条判断引用支持、问题完整性、恰当拒答。生成失败保留在题目分母，空结论不记100%引用支持；辅助评分失败不冒充答案错误或正确拒答。
- 相同答案只评分一次，三个离线线程运行；不重试生成挑结果。输入、模型身份、提示、源码及原始结果摘要均留档。
- 输出完整本地人工复核表和脱离原文大段正文的 Git 归档。评分明确标记同模型辅助、未经人工确认。

## 新增文件

- `PublicAnswerEvaluationCli`：测试目录中的显式真实模型入口，复用生产编排、保存初稿和最终结果、盲化组别评分；评分工具错误修复可以仅重评已有答案。
- `scripts/evaluate_public_answers.py`：冻结输入、编译运行、指标汇总、复核清单及脱敏归档。
- `scripts/test_evaluate_public_answers.py`：4 个关键统计用例，覆盖失败分母、空结论、缺评分与缺引用、评审路径遗漏或重复。
- `docs/evaluation/public-campus/ANSWERS.md`：设计、口径、复现和使用边界。
- `docs/evaluation/public-campus/runs/2026-11-24-answers.md/json`：80 题完整实验结果及典型失败分析。

## 修改文件

- `KnowledgeAnswerRecoveryEvaluationCli.service`：由私有改为包内可见，供新 CLI 共用冻结证据的测试组装；生产代码无变化。
- README、评测入口及公开语料说明：增加问答质量评测入口。

## API 与数据库

无新增或修改 HTTP API、数据库表、迁移。真实模型配置只读；评测不写用户会话，不切换默认库。

## 验证

- Maven `test-compile` 成功；Python 指标测试 4 项通过。
- 真实生成 80 题全部执行：有答案题基线交付 64/70，完整组交付 59/70；资料不足题分别交付 10/10、4/10。
- 最终同模型辅助评分：正确完整交付分别为 62/70、58/70；正确拒答 10/10、4/10；引用支持200/200、165/165。不能将这些数作为人工准确率。
- 首次评分器路径格式不一致，修复后只重评已有答案。原始错误评分和生成结果未覆盖；最终评分无协议或调用失败。
- 检查 `q043`、`n03`、`n08` 等疑似误拒，保留 `q035` 评审分歧及 `q071` 辅助评分自相矛盾案例。
- `git diff --check` 与 Python 编译检查通过。

## 局限与后续

- 本轮评测固定检索后的生成核验环节，不覆盖在线检索、多跳、上下文和前端渲染。
- 同模型评分存在共同偏差，原文参考及问题也未经独立人工复核。没有证据支持在简历宣称质量提升或100%引用正确。
- 当前发现复核可能扩大问题范围，以及资料不足/澄清状态与复核要求衔接不一致；本轮保留现状，不为追求分数修改生产逻辑。
- 先复核案例，再修复；若使用本轮题集调优，应另建独立测试题，不能继续称盲测。
